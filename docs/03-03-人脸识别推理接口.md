## 一、功能背景

识别是全系统的主业务：「这张脸是谁、有多像」。阶段 2 的 `recognize_from_image()` / `recognize_from_camera()` 已经跑通算法链路，但两者都绑定在 CLI 交互上（`input()` 路径、`imshow()` 预览、`waitKey` 控制循环），浏览器无法复用。

Web 侧存在两种**差异很大的识别场景**，必须在接口设计上分开：

| 场景 | 图片来源 | 关键诉求 | 语义词 |
|------|----------|----------|--------|
| **图片识别** | 用户上传本地照片 | 结果准确、可留档、可放大细看；单次请求 | 请求-响应（同步） |
| **实时识别** | 摄像头按帧上传 | 低延迟、可丢帧、画面连续；高频短请求 | 流式采样（允许丢弃） |

**为什么不直接调用 `FaceRecognition.recognize_face()`？**

| 现有实现 | 接口层需求 | 结论 |
|----------|------------|------|
| 每条人脸内部 `get_all_features()` 查一次库 | N 张脸 = N 次全表读 + N 次反序列化 | 改为**一次取库 + 批量矩阵运算** |
| 只返回 `{name, similarity}` 或 `None` | 需要人脸框坐标、`matched` 标记、未知脸也要返回 | 在接口层重新组装结果 |
| 无匹配时 `print("Error! 无匹配人脸...")` | 高频帧下会刷爆 stdout，且无级别控制 | 接口层改用 `logging.debug`，不复用该打印逻辑 |
| 阈值固定 `0.6` | 图片/实时场景可能需要不同阈值 | 暴露 `threshold` 参数（限定 0.3~0.95） |

> **结论**：接口层复用 `FaceRecognition.extract_feature()`（特征提取）与 `db_utils.face_db.get_all_features()`（取库），**自行完成批量比对与结果组装**；`recognize_face()` 保留给 CLI 使用，两者算法口径一致（余弦相似度 + 同一阈值默认值）。

## 二、开发目标

| 目标 | 说明 |
|------|------|
| 图片识别 | 上传图片 → 返回全部人脸框、姓名、相似度、是否匹配；可选取回标注结果图 |
| 帧识别 | 接收 base64 帧 → 同口径识别，面向实时叠加，不保存图片 |
| 批量比对 | 一次取库拼 `(N,512)` 矩阵，N 张脸只做 1 次向量化运算 |
| 空库可读 | 特征库为空时正常返回人脸框，`library_empty=true` 并提示录入，不报错 |
| 阈值可调 | `threshold ∈ [0.3, 0.95]`，默认 0.6；越界返回 `1001`（非数字由框架返回 `422`） |
| 坐标正确 | 所有 `box` 基于**原图坐标系**，大图内部缩放必须按比例还原 |
| 实时可承受 | 单帧推理串行化 + 非阻塞丢帧（`1008` / 429），避免请求堆积 |
| 可留档 | `save_result=true` 时保存标注图到 `result_output/`，返回 `/static/...` URL |

## 三、功能职责

| 分类 | 函数 | 职责 |
|------|------|------|
| 共用服务 | `_recognize_bgr(image, threshold, save_result=False, prefix='api') -> RecognizeData` | 检测 → 特征 → 批量比对 → 组装结果（可选保存标注图） |
| 路由 | `recognize_by_image(file, threshold, save_result)` | 解析 `multipart`，同步路由（线程池） |
| 路由 | `recognize_by_frame(payload)` | 解析 JSON + base64，非阻塞锁保护 |
| 并发保护 | `_infer_lock` | 保证同一时刻只有 1 个请求在跑模型（帧接口丢弃、图片接口排队） |
| 标注（复用） | `main.draw_results()` / `main.save_result()` | 可选保存标注图，复用阶段 2 的中文绘制能力 |

**不做的事**：

- 不做前端 canvas 叠加绘制（→ 阶段 4 `ImageRecognize.vue` / `CameraRealTime.vue`）；
- 不返回整张图片的 base64（大图会撑爆 JSON，改为 `save_result` + 静态 URL）；
- 不做多帧跟踪 / 人脸 ID 维持（实时页仅按帧独立识别）；
- 不做人脸质量评分、活体检测（后置优化项）。

## 四、功能逻辑

### 4.1 接口定义

| 接口 | 方法 | 路径 | Content-Type | 参数 | 成功响应 `data` |
|------|------|------|--------------|------|-----------------|
| 图片识别 | `POST` | `/api/recognize/image` | `multipart/form-data` | `file`（必填）、`threshold`（可选，默认 0.6）、`save_result`（可选，默认 `false`） | `RecognizeData` |
| 帧识别 | `POST` | `/api/recognize/frame` | `application/json` | `image_base64`（必填）、`threshold`（可选，默认 0.6） | `RecognizeData` |

```python
@app.post('/api/recognize/image', response_model=ApiResponse[RecognizeData], tags=['recognize'])
def recognize_by_image(file: UploadFile = File(...),
                       threshold: float = Form(DEFAULT_THRESHOLD),
                       save_result: bool = Form(False)):
    if not THRESHOLD_MIN <= threshold <= THRESHOLD_MAX:
        return fail(1001, f'阈值需在 {THRESHOLD_MIN} ~ {THRESHOLD_MAX} 之间')
    raw = file.file.read()
    image = decode_upload_image(raw) if raw and len(raw) <= MAX_UPLOAD_BYTES else None
    if image is None:
        return fail(1001, '图片为空、超过 5MB 或格式不支持')
    with _infer_guard(blocking=True):            # 图片识别排队等待，超时返回 1008
        data = _recognize_bgr(image, threshold, save_result=save_result, prefix='api_image')
    return ok(data)


@app.post('/api/recognize/frame', response_model=ApiResponse[RecognizeData], tags=['recognize'])
def recognize_by_frame(payload: FrameRecognizeRequest):
    if not THRESHOLD_MIN <= payload.threshold <= THRESHOLD_MAX:
        return fail(1001, f'阈值需在 {THRESHOLD_MIN} ~ {THRESHOLD_MAX} 之间')
    image = decode_base64_image(payload.image_base64)
    if image is None:
        return fail(1001, '帧数据为空或非法 base64')
    if not _infer_lock.acquire(blocking=False):  # 实时链路优先丢帧，不排队
        return fail(1008, '推理服务繁忙，请丢弃当前帧', status_code=429)
    try:
        data = _recognize_bgr(image, payload.threshold)
    finally:
        _infer_lock.release()
    return ok(data)
```

并发保护具体实现（`_infer_guard` 为图片接口使用的带超时上下文管理器）：

```python
_infer_lock = threading.Lock()                    # 同一时刻只允许 1 个推理任务
_INFER_TIMEOUT = 10.0                             # 图片识别最长排队 10s

@contextmanager
def _infer_guard(blocking=True, timeout=_INFER_TIMEOUT):
    acquired = _infer_lock.acquire(blocking=blocking, timeout=timeout if blocking else -1)
    if not acquired:
        raise TimeoutError('推理服务繁忙')
    try:
        yield
    finally:
        _infer_lock.release()
```

> 路由必须保持**同步 `def`**：模型推理会长时间占用 CPU/GPU，放进线程池才不会阻塞事件循环；因此 `_infer_lock` 用普通 `threading.Lock` 而非 `asyncio.Lock`。

### 4.3 处理流程

```text
/api/recognize/image  (multipart: file, threshold, save_result)
/api/recognize/frame  (JSON: image_base64, threshold)
        │
        ├─ 1. 解码 + 大小校验                           失败 → 1001
        ├─ 2. 获取推理锁:
        │      图片: 阻塞等待 ≤10s                      超时 → 1008
        │      帧  : 非阻塞，拿不到立即返回              失败 → 1008 (429)
        ├─ 3. 大图缩放: limit_max_side(image, 1280) → (img, scale)
        ├─ 4. 人脸检测: detector.detect_faces(img)
        │      无人脸                                    → 1002
        │      坐标除以 scale 还原到原图坐标系（见 4.5）
        ├─ 5. 取库: db_utils.face_db.get_all_features()
        │      库空 → library_empty=True，全部 face 记为未匹配，跳过 6/7
        │      库非空 → library_matrix (N,512) + info_list
        ├─ 6. 逐脸特征: FaceRecognition.extract_feature(roi)
        │      失败(None) → 该脸 matched=false、similarity=0，继续下一张
        ├─ 7. 批量比对: sims = library_matrix @ feature.T   → 取 argmax
        │      similarity >= threshold ? matched=true + name : matched=false
        ├─ 8. 统计: total_faces / matched_count / elapsed_ms
        └─ 9. save_result=true → main.draw_results + main.save_result
               → result_image_url = '/static/<filename>.jpg'
```

### 4.4 批量比对实现（相对 CLI 的关键优化）

```python
def _recognize_bgr(image, threshold, save_result=False, prefix='api'):
    started = time.perf_counter()
    img, scale = limit_max_side(image)                     # 长边 > 1280 才缩放
    raw_faces = detector.detect_faces(img)
    if not raw_faces:
        return 1002, '未检测到人脸', None

    inv = 1.0 / scale                                      # 坐标还原系数
    matrix, info_list = db_utils.face_db.get_all_features()   # 一次取库
    library_empty = matrix is None or not info_list

    results = []
    for roi, (x, y, w, h) in FaceDetection.crop_face_rois(img, raw_faces):
        box = FaceBox(x=round(x * inv), y=round(y * inv),
                      w=round(w * inv), h=round(h * inv))
        feature = FaceRecognition.extract_feature(roi)        # (1,512) 且已 L2 归一
        if feature is None or library_empty:
            results.append(FaceResult(box=box, name=None, similarity=0.0, matched=False))
            continue
        sims = matrix @ feature.reshape(-1)                   # (N,512)·(512,) → (N,)
        idx = int(np.argmax(sims))
        similarity = float(sims[idx])
        matched = similarity >= threshold
        results.append(FaceResult(box=box,
                                  name=info_list[idx]['name'] if matched else None,
                                  similarity=round(similarity, 4),
                                  matched=matched))

    data = RecognizeData(total_faces=len(results),
                         matched_count=sum(1 for r in results if r.matched),
                         elapsed_ms=int((time.perf_counter() - started) * 1000),
                         library_empty=library_empty,
                         faces=results)
    if save_result:
        data.result_image_url = f'/static/{_write_result(draw_annotated(image, results), prefix)}'
    message = ('特征库为空，请先录入人脸' if library_empty
               else f'识别完成: {data.matched_count}/{data.total_faces} 人匹配成功')
    return 0, message, data
```

| 维度 | CLI `recognize_face()` | 接口 `_recognize_bgr()` |
|------|------------------------|--------------------------|
| 取库次数 | 每张脸 1 次 | 每次请求 1 次 |
| 相似度计算 | `sklearn.cosine_similarity` | `matrix @ feature`（特征已 L2 归一，点积即余弦） |
| 结果粒度 | 单脸 `{name, similarity}` | 全部人脸，含框、`matched`、未命中项 |
| 空库 | 打印 Warning 返回 `None` | `library_empty=true` + 空结果，HTTP 200 |
| 日志 | `print` | `logging.debug`（高频帧不刷屏） |

> **数学等价说明**：`extract_feature` 内已执行 `embedding / ||embedding||₂`，库中存的是同一批归一化向量，因此 `a·b` 等价于 `cos(a,b)`；与 `sklearn.cosine_similarity` 结果一致，但省去逐脸构造二维矩阵与归一化开销。

### 4.5 坐标契约（重要）

```text
原图 4000×3000 ──limit_max_side(1280)──► 推理图 1280×960   scale = 0.32
                                            │
                                     检测得框 (x', y', w', h')
                                            │
      响应必须回传原图坐标: x = x'/0.32, y = y'/0.32, w = w'/0.32, h = h'/0.32
                                            │
前端 <canvas> 按 naturalWidth/displayWidth 再缩放 ──► 屏幕坐标
```

| 环节 | 使用的坐标系 | 常见错误 |
|------|--------------|----------|
| 服务端检测 | 缩放后图像 | 直接把缩放坐标返回 → 前端框偏小且向左上偏移 |
| 服务端响应 `box` | **原图** | — |
| 前端 canvas | 显示尺寸 | 忘记乘 `displayWidth / naturalWidth` → 高分屏/响应式布局下框错位 |

### 4.6 阈值语义

| `threshold` | 行为 | 适用场景 | 风险 |
|-------------|------|----------|------|
| 0.3 ~ 0.5 | 命中宽松 | 演示、样本质量差异大 | 不同人被误认成同一人（误识率上升） |
| **0.6（默认）** | 平衡 | 常规图片识别 / 实时识别 | 与 CLI 默认一致，便于结果对齐 |
| 0.7 ~ 0.95 | 命中严格 | 门禁级场景、要求高置信 | 同人多角度/侧光可能漏判 |

> 阈值是**经验值**，须用 `backend/sample_faces/` 的真实样本在 0.5 ~ 0.7 区间标定后固化（见 `docs/02-02` 坑点 10、`docs/02-04` 坑点 11）。

### 4.7 实时帧节流与丢帧

```text
前端: setInterval/递归 setTimeout ── 每 300~500ms 抓 1 帧 ──► POST /api/recognize/frame
                                                    │
后端: 非阻塞抢锁 ── 成功 ──► 推理（80~200ms）──► 200 + faces
                 └─ 失败 ──► 429 + code=1008（立即返回，不占线程）
```

| 策略 | 取值 | 说明 |
|------|------|------|
| 前端发送间隔 | 300 ~ 500 ms | 低于 300ms 只增加负载，不提升观感 |
| 帧分辨率 | 640×480 | 再压缩到 JPEG q0.8，约 30~80 KB |
| 后端并发 | 1（`_infer_lock`） | 保证 GPU/CPU 不排队、延迟可控 |
| 忙时行为 | 立即 `1008` | 前端静默丢弃该帧，保留上一帧画面 |
| 超时 | 前端 `axios` timeout 5s | 超时同样静默丢帧，不弹错误 |

### 4.8 标注结果图（`save_result`）

- 仅图片识别支持 `save_result=true`；帧接口固定不保存（避免每次请求写盘）。
- 标注逻辑复用 `main.draw_results()` + `main.put_chinese_text()`，因此依赖 `C:/Windows/Fonts/simhei.ttf`；字体缺失时 `put_chinese_text` 已内置降级，不会中断。
- 文件名由接口层生成（时间戳 + 微秒），**不复用** `main.save_result()` 的 `print`，避免日志污染。
- 通过 `app.mount('/static', StaticFiles(directory=RESULT_DIR), name='static')` 暴露；返回相对路径 `/static/<name>.jpg`，由前端拼接 `baseURL` 主机部分。

```python
def draw_annotated(image, results):
    """把 RecognizeData.faces 转成 main.draw_results 需要的 (faces, infos) 结构"""
    faces = [(r.box.x, r.box.y, r.box.w, r.box.h) for r in results]
    infos = [{'name': r.name, 'similarity': r.similarity} if r.matched else None
             for r in results]
    return main.draw_results(image.copy(), faces, infos)     # 绿框=命中, 红框=未知


def _write_result(image, prefix):
    """保存标注图，返回文件名（不打印，避免污染接口日志）"""
    name = f'{prefix}_{time.strftime("%Y%m%d_%H%M%S")}_{int(time.time() * 1e6) % 1000000}.jpg'
    ok_flag, buffer = cv2.imencode('.jpg', image)
    if not ok_flag:
        raise IOError('标注图编码失败')
    with open(os.path.join(RESULT_DIR, name), 'wb') as f:
        f.write(buffer)
    return name
```

## 七、异常点与坑点

| # | 问题 | 现象 | 定位与处置 |
|---|------|------|------------|
| 1 | **逐脸查库** | 直接调用 `recognize_face()`，N 张脸读 N 次全表 + N 次 `vstack`，多脸图明显变慢 | 每次请求只 `get_all_features()` 一次，后续用矩阵点积批量比对 |
| 2 | **`sklearn` 逐脸调用开销** | 每张脸构造一次 `cosine_similarity`，小矩阵下函数开销占比高 | 特征已 L2 归一，直接 `matrix @ feature`，与余弦完全等价 |
| 3 | **坐标未还原** | 大图内部缩放到 1280 后检测，直接把缩放坐标返回 → 前端框偏小、整体左上偏移 | 统一乘 `1/scale` 并 `round` 取整；`docs/03-05` 用大图用例锁定 |
| 4 | **帧请求排队** | 前端 5 帧/秒、单帧 200ms，若用阻塞锁会越积越多，延迟持续上涨 | 帧接口 `acquire(blocking=False)`，拿不到锁立即 `1008`；前端静默丢帧 |
| 5 | **锁粒度影响图片识别** | 与帧接口共用一把锁且都设置超时，图片识别被实时页挤掉 | 图片接口用带超时（10s）的阻塞获取，帧接口非阻塞；超时返回 `1008` |
| 6 | **`threshold` 来自 Form** | multipart 里 `threshold` 是字符串，传 `abc` 时 FastAPI 转换失败 → `422` 而非 `1001` | `422` 由统一异常处理器转成信封，前端按 `code` 处理；语义上属参数错误，可接受 |
| 7 | **`save_result` 布尔解析** | `FormData.append('save_result', false)` 实际发送字符串 `"false"`；传空字符串报 422 | 前端显式传 `'true'` / `'false'`；FastAPI 支持 `true/false/1/0/on/off` |
| 8 | **空库导致前端弹错** | 若空库返回 `1006` 之类错误码，实时页会每秒弹一次提示 | 空库走 `code=0 + library_empty=true`，前端画红框 + 常驻提示（本文档 4.2） |
| 9 | **`extract_feature` 静默失败** | ROI 过小/通道异常时内部 `try/except` 返回 `None`，接口若未判空会 `AttributeError` | 逐脸判 `None`，该脸记为未匹配并继续；同时记录 `logging.warning` |
| 10 | **`CascadeClassifier` 非线程安全** | 多线程并发 `detectMultiScale` 偶发崩溃或结果错乱 | 全局 `_infer_lock` 已把检测+特征串行化；不要为「提速」去掉该锁 |
| 11 | **摄像头预览镜像导致框左右翻转** | 预览用 `transform: scaleX(-1)`，但 canvas 按原坐标绘制 → 左右框错位 | 预览不镜像，或用 `canvas.width - x - w` 换算；详见 `docs/04-04` |
| 12 | **相似度精度展示不一致** | 接口返回 4 位小数、CLI 打印 2 位，联调时误判「结果不同」 | 一致性比对用未取整值或统一到 4 位；展示层再格式化 |
| 13 | **结果图无限增长** | 每次 `save_result` 落盘一张，长期运行占用磁盘 | 默认 `false`；定期清理 `result_output/`，或在阶段 5 增加保留策略 |
| 14 | **多脸 ROI 与框顺序错位** | 若先过滤/排序人脸再裁剪，`faces` 与 `rois` 顺序不一致 | 严格复用 `crop_face_rois(img, raw_faces)` 返回顺序，逐项同序组装 |
