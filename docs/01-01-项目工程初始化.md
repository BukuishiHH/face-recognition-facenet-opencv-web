## 一、功能背景

本系统（`face-recognition-facenet-opencv-web`）需要交付「底层人脸算法 → FastAPI 后端 → Vue3 前端 → 可选 PyQt 桌面端」的完整链路。多阶段、多模块协作开发要求工程在最初就具备：

1. **职责清晰的目录边界**——算法、接口、界面、文档互不混杂；
2. **可复现的依赖声明**——避免「我这能跑」的环境差异；
3. **正确的版本控制策略**——数据库、二进制模型、中人脸隐私图片不得进入 Git 历史。

因此阶段 1 的第一个动作不是写业务代码，而是先立好工程骨架与版本控制规矩，为后续所有阶段提供稳定地基。

## 四、功能逻辑

### 4.1 目录结构设计

```text
face-recognition-facenet-opencv-web/
├── backend/                     # 核心算法层 + 接口层 (Python)
│   ├── sample_faces/            # 人脸样本集 [姓名]/*.jpg (隐私数据, 已忽略)
│   ├── result_output/           # 识别结果输出图 (运行时产物, 已忽略)
│   ├── face_detection.py        # (阶段2-1) Haar 人脸检测
│   ├── face_recognition.py      # (阶段2-2) FaceNet 特征提取与比对
│   ├── db_utils.py              # (阶段2-3) SQLite 特征库
│   ├── main.py                  # (阶段2-4) CLI 业务编排
│   ├── api_server.py            # (阶段3)   FastAPI 服务
│   └── face_features.db         # (运行时生成) 特征库 (已忽略)
├── frontend/                    # (阶段4) Vue3 + Vite 前端工程
├── docs/                        # 全部开发文档 (阶段/模块文档 + 总纲)
├── temp/                        # 本地临时文件 (已忽略, 存放人工操作指导文档)
├── requirements.txt             # Python 依赖清单
├── .gitignore                   # 版本控制忽略规则
└── README.md                    # 项目入口说明
```

### 4.2 `.gitignore` 忽略策略

在 GitHub 官方 `Python.gitignore` 模板基础上，追加**项目专属规则**：

| 忽略项 | 规则 | 原因 |
|--------|------|------|
| Python 缓存/字节码 | `__pycache__/`、`*.py[codz]` | 模板自带，避免污染提交 |
| 虚拟环境 | `venv/`、`cv_demo/`、`.venv` | 环境严禁入库，靠 `requirements.txt` 重建 |
| 特征数据库 | `*.db`、`backend/face_features.db` | 运行时生成，含二进制特征，无需入库 |
| 人脸样本图 | `backend/sample_faces/*`（白名单 `.gitkeep`） | **隐私合规**：真实人脸数据不进版本库 |
| 识别结果图 | `backend/result_output/*`（白名单 `.gitkeep`） | 运行时产物，体积不可控 |
| 本地临时目录 | `temp/` | 存放本地人工操作指导、下载缓存 |

> 采用 `目录/*` + `!目录/.gitkeep` 的写法，既忽略全部内容物，又能让空目录在克隆后保留。

### 4.3 `requirements.txt` 依赖约束策略

- **`opencv-python>=4.8,<5`**：`opencv-python 5.x` 已彻底移除 `cv2.CascadeClassifier`，会导致 Haar 检测模块直接不可用，必须锁定 4.x（详见「六、异常点与坑点」）。
- `numpy>=1.24,<3`：兼顾 opencv 4.x 与 torch 2.x 的兼容区间。
- `torch` / `facenet-pytorch`：体积数百 MB，**不在批量安装范围**，由人工按 `temp/TORCH_INSTALL_GUIDE.md` 安装。
- 其余（`fastapi`、`uvicorn`、`python-multipart`、`Pillow`、`pytest`）：给出下限约束，允许补丁级更新。

### 4.4 版本控制与分支策略

- 主分支 `main` 承载全流程正线开发；
- 可选 PyQt 桌面开发（阶段 5-2）必须隔离到 `pyqt-desktop` 分支；
- 每个 Step 完成后独立提交，保持提交粒度可回溯。

## 六、异常点与坑点

| # | 问题 | 现象 | 处置 |
|---|------|------|------|
| 1 | **opencv-python 5.x 移除 `CascadeClassifier`** | `cv_demo` 环境实测 `cv2.__version__ == 5.0.0`、`hasattr(cv2,'CascadeClassifier') == False`，Haar 检测不可用 | `requirements.txt` 锁定 `>=4.8,<5`，并在环境搭建阶段强制降级 |
| 2 | 人脸样本图误入库 | 样本含真实人脸，涉及隐私且体积大 | `.gitignore` 忽略 `backend/sample_faces/*`，仅在仓库保留 `.gitkeep` |
| 3 | 特征库 `face_features.db` 误入库 | 二进制 BLOB 无法 diff，且随运行膨胀 | 忽略 `*.db` |
| 4 | 空目录无法被 Git 跟踪 | 仅建目录会在克隆后消失 | 每个需保留的空目录放置 `.gitkeep` |
| 5 | 项目内创建虚拟环境会污染提交 | `venv/` 数千文件 | 忽略 `venv/`、`cv_demo/`，环境通过 `requirements.txt` 重建 |
