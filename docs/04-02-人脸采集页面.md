## 一、功能背景

「把人脸存进特征库」是全部业务的起点。CLI 有两条采集路径，Web 端必须一一对应，但交互形态完全不同：

| CLI 能力 | 实现方式 | Web 化后的形态 | 关键差异 |
|----------|----------|----------------|----------|
| `register_face_from_image()` | `input()` 取本地路径 → `imread` | `<input type="file">` 上传字节 | 浏览器拿不到服务器路径，只能上传 |
| `register_face_from_camera()` | `VideoCapture(0)` + `imshow()` + `input()` 取姓名 | `getUserMedia` 预览 → `canvas` 截帧 → base64 上传 | 摄像头在用户侧，服务端不接触设备 |
| 姓名输入 | `input()` 文本 | 受控输入框 + 前置校验 | 需处理中文 IME、纯空格、超长 |

页面上采用**同一路由、双模式切换**，而不是两个页面：

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **一个页面两个模式（Tab）** | 姓名输入、回执、提示区可复用；用户来回切换不丢上下文；导航只占一项 | 组件内状态略多 | ✅ 选用 |
| 两个独立页面 | 组件更小 | 导航变 6 项；姓名/提示逻辑复制两份；切换需重新输入 | ✗ |
| 只做上传，拍照跳转实时识别页 | 复用 4-4 摄像头 | 语义混乱（识别页不应写库）；实时页有定时器开销 | ✗ |

**为什么拍照后上传「一帧」而不是持续视频流**：阶段 3 的 `/api/face/register/camera-frame` 接收单张 `image_base64`，一次拍照 = 一次入库请求，语义清晰、失败可重试；连续流入库会产生同名 `1004`，且用户无法确认「用的是哪一帧」。

**为什么抽 `useCamera` composable**：4-2（拍照入库）与 4-4（实时识别）都需要「申请权限 → 绑定 `<video>` → 截图 → 释放」，差异只在截图频率与后续请求。抽成 composable 后，两页共享同一套权限错误文案与资源释放逻辑，避免实时页修好、采集页仍泄漏摄像头。

## 二、开发目标

| 目标 | 说明 |
|------|------|
| 模式一可入库 | 选择本地图片 + 姓名 → 调用 `/api/face/register/image` → 展示 `record_id` |
| 模式二可入库 | 开启摄像头 → 预览 → 拍照 → 姓名 → 调用 `/api/face/register/camera-frame` |
| 输入前置校验 | 姓名 `trim` 后 1~32 字符；图片类型 JPG/PNG/WEBP/BMP、非空、≤ 5 MB |
| 大图压缩 | 本地图片长边 > 1600 时按比例压缩为 JPEG（q0.85），避免上传超限与慢速 |
| 拍照可控 | 拍照后进入「已拍摄」态，可**重拍**或**确认入库**，不会误传糊帧 |
| 提交防重 | 请求进行中按钮 `disabled` + loading 文案；重复点击复用同一 `AbortController` 规则 |
| 回执清晰 | 成功展示 `record_id / name / face_count / feature_dim`；`face_count > 1` 时提示「已取最大人脸」 |
| 错误可读 | `1001 / 1002 / 1003 / 1004 / 1007 / 422 / -1 / -2` 均有中文提示，`1004` 附「去特征库管理」入口 |
| 资源不泄漏 | 切换模式、路由离开、页面隐藏时停止轨道；`objectURL` 及时 `revokeObjectURL` |
| 响应式 | ≥1024px 左预览右表单；窄屏上下堆叠；摄像头预览不溢出 |

## 三、功能职责

| 分类 | 成员 | 职责 |
|------|------|------|
| 页面状态 | `mode` | `'upload'` / `'camera'`，切换时清理另一模式的资源 |
| 页面状态 | `realName`、`selectedFile`、`previewUrl`、`captured` | 表单与预览数据 |
| 页面状态 | `status`、`submitting`、`errorText`、`receipt`、`notice` | 交互态与回执 |
| 组件方法 | `onFileChange()` / `clearSelected()` | 校验、压缩、生成预览、释放旧 URL |
| 组件方法 | `switchMode()` | 切换模式，停止摄像头 / 清空拍照结果 |
| 组件方法 | `startCamera()` / `stopCamera()` / `takePhoto()` / `retake()` | 摄像头生命周期与截图 |
| 组件方法 | `submit()` | 姓名与图片校验 → 调用接口 → 渲染回执 / 错误 |
| composable | `useCamera()` | `getUserMedia`、设备枚举、`capture()`、错误文案、卸载释放 |
| 工具 | `validateImageFile()` / `scaleSize()` / `compressImage()` | 复用 4-1，新增压缩函数 |

**不做的事**：

- 不做同一姓名多张样本追加（后端 `exists_name` 语义是「同名即同一人」，第二条返回 `1004`）；
- 不做人脸裁剪、美颜、旋转校正、活体检测（后置优化项）；
- 不做批量上传（一次一张，保证错误定位清晰）；
- 不做「覆盖录入」（覆盖 = 去特征库页删除后重新采集，见 `docs/03-04`）；
- 不在采集页绘制人脸框（后端返回的 `selected` 仅用于提示，不做坐标叠加）。

### 4.2 交互状态机

```text
                 ┌──────────┐
     进入页面 ──►│  idle    │◄──────────── 清除 / 重拍 / 切换模式
                 └────┬─────┘
     选择图片/拍照     │
                 ┌────▼──────────┐
                 │  previewing   │  可修改姓名、可重拍
                 └────┬──────────┘
             点击确认 │（校验通过）
                 ┌────▼──────────┐
                 │  submitting   │  按钮禁用、Tab 禁用
                 └──┬─────────┬──┘
            成功   │         │ 失败（ApiError）
              ┌────▼───┐ ┌───▼────────┐
              │ receipt│ │ error      │ 保留预览与姓名，可直接重试
              └────────┘ └────────────┘
```

| 状态 | 可交互项 | 说明 |
|------|----------|------|
| `idle` | Tab、姓名、选择图片/开启摄像头 | 无预览 |
| `previewing` | Tab、姓名、重拍/清除、确认入库 | 有预览；提交前置校验 |
| `submitting` | 仅「取消」 | 其余按钮 `disabled`；Tab 禁止切换 |
| `receipt` | Tab、姓名、重新采集 | 展示回执；已清空图片，避免误重复提交 |
| `error` | Tab、姓名、重试 | 保留图片与姓名，`1004` 额外显示删除入口 |

> 提交成功后**清空图片但保留姓名输入**：用户可一眼确认「刚才是谁入库」，同时必须重新选择图片才能再次提交，从交互上规避同名 `1004`。

### 4.3 模式一：本地图片上传

```vue
<!-- frontend/src/views/FaceCollect.vue（核心片段） -->
<script setup>
import { computed, onBeforeUnmount, ref } from 'vue'
import { registerByFrame, registerByImage, MAX_NAME_LEN, MAX_UPLOAD_BYTES } from '../api/face'
import { compressImage, validateImageFile } from '../utils/image'
import { toUserMessage } from '../utils/errors'
import { useCamera } from '../composables/useCamera'

const mode = ref('upload')                 // upload | camera
const realName = ref('')
const selectedFile = ref(null)             // 压缩后的 File（上传给后端）
const previewUrl = ref('')
const captured = ref(null)                 // { dataUrl, width, height }
const status = ref('idle')                 // idle | previewing | submitting | receipt | error
const errorText = ref('')
const notice = ref('')
const receipt = ref(null)
const uploadPercent = ref(0)
let submitController = null

const nameLength = computed(() => [...realName.value.trim()].length)
const canSubmit = computed(() =>
  nameLength.value >= 1 && nameLength.value <= MAX_NAME_LEN && status.value !== 'submitting'
  && (mode.value === 'upload' ? !!selectedFile.value : !!captured.value),
)

function releasePreview() {
  if (previewUrl.value) URL.revokeObjectURL(previewUrl.value)
  previewUrl.value = ''
}

/** 压缩实现统一放在 utils/image.js（见 docs/04-01 4.10），本页只调用 */

async function onFileChange(event) {
  const file = event.target.files && event.target.files[0]
  event.target.value = ''                              // 允许再次选择同一文件
  if (!file) return
  const invalid = validateImageFile(file, MAX_UPLOAD_BYTES)
  if (invalid) { errorText.value = invalid; status.value = 'error'; return }
  try {
    selectedFile.value = await compressImage(file)
  } catch (err) {
    errorText.value = err.message || '图片处理失败'
    status.value = 'error'
    return
  }
  releasePreview()
  previewUrl.value = URL.createObjectURL(selectedFile.value)
  captured.value = null
  receipt.value = null
  errorText.value = ''
  notice.value = ''
  status.value = 'previewing'
}
</script>
```

| 处理环节 | 规则 | 失败表现 |
|----------|------|----------|
| 类型校验 | 仅 `image/jpeg` / `image/png` / `image/webp` / `image/bmp` | 提示「仅支持 JPG / PNG / WEBP / BMP 图片」 |
| 大小校验 | `file.size ≤ 5 MB`（与后端 `MAX_UPLOAD_BYTES` 一致） | 提示具体 MB 数 |
| 压缩阈值 | 原始 ≤ 800 KB 直接上传；否则长边压到 1600、JPEG q0.85 | 压缩失败提示重试 |
| 文件名 | 压缩后统一 `collect_<时间戳>.jpg` | — |
| 预览 | `URL.createObjectURL`，替换前先 `revoke` | — |
| 重置 | `input.value = ''` | 否则同一文件二次选择不触发 `change` |

> **压缩阈值不是越小越好**：长边 1600 已足够 Haar 检测与 FaceNet 输入（ROI 最终缩放到 160×160），继续压到 800 会让远距离小脸丢失细节，反而触发 `1002`。

### 4.4 模式二：摄像头预览与拍照

`useCamera` 统一负责权限、设备与释放，4-2 与 4-4 共用：

```js
// frontend/src/composables/useCamera.js
import { onBeforeUnmount, ref, shallowRef } from 'vue'
import { scaleSize } from '../utils/image'

const ERROR_TEXT = {
  NotAllowedError: '摄像头权限被拒绝，请点击地址栏的相机图标允许访问后重试',
  PermissionDeniedError: '摄像头权限被拒绝，请点击地址栏的相机图标允许访问后重试',
  NotFoundError: '未检测到可用摄像头设备',
  DevicesNotFoundError: '未检测到可用摄像头设备',
  NotReadableError: '摄像头被其他程序占用，请关闭会议 / 直播软件后重试',
  TrackStartError: '摄像头被其他程序占用，请关闭占用摄像头的应用后重试',
  OverconstrainedError: '当前摄像头不支持请求的分辨率，请切换设备后重试',
  SecurityError: '当前页面不是安全上下文，请通过 127.0.0.1 / localhost 或 HTTPS 访问',
}

export function useCamera({ width = 640, height = 480, facingMode = 'user' } = {}) {
  const videoRef = ref(null)
  const stream = shallowRef(null)      // MediaStream 不需要深层响应
  const status = ref('idle')           // idle | starting | ready | error
  const errorText = ref('')
  const devices = ref([])
  const activeDeviceId = ref('')

  async function start(deviceId = '') {
    stop()
    status.value = 'starting'
    errorText.value = ''
    if (!navigator.mediaDevices || !navigator.mediaDevices.getUserMedia) {
      status.value = 'error'
      errorText.value = '当前浏览器不支持摄像头采集，请使用 Chrome / Edge 最新版'
      return false
    }
    const constraints = {
      audio: false,
      video: {
        width: { ideal: width },
        height: { ideal: height },
        ...(deviceId ? { deviceId: { exact: deviceId } } : { facingMode }),
      },
    }
    try {
      stream.value = await navigator.mediaDevices.getUserMedia(constraints)
    } catch (err) {
      status.value = 'error'
      errorText.value = ERROR_TEXT[err.name] || `摄像头启动失败：${err.message}`
      return false
    }
    if (videoRef.value) {
      videoRef.value.srcObject = stream.value
      try {
        await videoRef.value.play()
      } catch {
        /* 自动播放被策略拦截时，由用户点击 video 手动播放 */
      }
    }
    const track = stream.value.getVideoTracks()[0]
    activeDeviceId.value = deviceId || (track && track.getSettings().deviceId) || ''
    await refreshDevices()
    status.value = 'ready'
    return true
  }

  function stop() {
    if (stream.value) {
      stream.value.getTracks().forEach((track) => track.stop())
      stream.value = null
    }
    if (videoRef.value) videoRef.value.srcObject = null
    if (status.value !== 'error') status.value = 'idle'
  }

  /** 首次授权前 label 为空，必须在 getUserMedia 成功后再枚举 */
  async function refreshDevices() {
    if (!navigator.mediaDevices || !navigator.mediaDevices.enumerateDevices) return
    try {
      const list = await navigator.mediaDevices.enumerateDevices()
      devices.value = list.filter((item) => item.kind === 'videoinput')
    } catch {
      devices.value = []
    }
  }

  /** 从当前帧截图；长边压到 maxWidth，返回 { dataUrl, width, height } */
  function capture({ maxWidth = 640, quality = 0.8 } = {}) {
    const video = videoRef.value
    if (!video || !video.videoWidth || !video.videoHeight) return null
    const size = scaleSize(video.videoWidth, video.videoHeight, maxWidth)
    const canvas = document.createElement('canvas')
    canvas.width = size.width
    canvas.height = size.height
    canvas.getContext('2d').drawImage(video, 0, 0, size.width, size.height)
    return { dataUrl: canvas.toDataURL('image/jpeg', quality), width: size.width, height: size.height }
  }

  onBeforeUnmount(stop)

  return { videoRef, stream, status, errorText, devices, activeDeviceId, start, stop, refreshDevices, capture }
}
```

| 能力 | 取值 / 行为 | 说明 |
|------|-------------|------|
| 分辨率 | `ideal 640×480` | 640 宽足够检测，且单帧 base64 ≈ 40~80 KB |
| 音频 | `audio: false` | 不申请麦克风，减少授权阻力 |
| 设备枚举 | 授权成功后 `enumerateDevices` | 授权前 `label` 为空，无法区分摄像头 |
| 截图 | `video.videoWidth/Height` → canvas → JPEG q0.8 | **不能**用 `clientWidth`（含 CSS 缩放） |
| 释放 | `getTracks().forEach(t => t.stop())` | 仅 `srcObject = null` 不会释放设备 |
| 卸载 | `onBeforeUnmount(stop)` | 路由离开必须停轨，见 4.7 |

```js
// FaceCollect.vue 续：摄像头相关逻辑
const camera = useCamera({ width: 640, height: 480 })
const { videoRef } = camera
const cameraReady = computed(() => camera.status.value === 'ready')

async function startCamera() {
  releasePreview()
  captured.value = null
  receipt.value = null
  errorText.value = ''
  const ok = await camera.start(camera.activeDeviceId.value)
  if (!ok) { errorText.value = camera.errorText.value; status.value = 'error' }
}

function takePhoto() {
  const shot = camera.capture({ maxWidth: 640, quality: 0.8 })
  if (!shot) { errorText.value = '画面尚未就绪，请等待 1 秒后重试'; return }
  captured.value = shot
  errorText.value = ''
  notice.value = `已拍摄 ${shot.width}×${shot.height} 画面，确认无误后点击「确认入库」`
  status.value = 'previewing'
}

function retake() {
  captured.value = null
  notice.value = ''
  errorText.value = ''
  status.value = cameraReady.value ? 'idle' : 'error'
}

async function switchMode(next) {
  if (status.value === 'submitting' || next === mode.value) return
  mode.value = next
  receipt.value = null
  notice.value = ''
  errorText.value = ''
  if (next === 'upload') {
    camera.stop()
    captured.value = null
    status.value = selectedFile.value ? 'previewing' : 'idle'
  } else {
    clearSelected()
    selectedFile.value = null
    if (!cameraReady.value) await startCamera()
    else status.value = captured.value ? 'previewing' : 'idle'
  }
}

function clearSelected() {
  releasePreview()
  selectedFile.value = null
  if (mode.value === 'upload') status.value = 'idle'
}
```

> **预览不做镜像**：镜子式预览会让用户以为自己的左右手与画面对应，但截图后画面又是未镜像的，容易出现「拍照时脸偏左、照片里偏右」的困惑。统一不镜像，做到所见即所得；若产品坚持镜像，必须同时给 canvas 做 `ctx.translate(w,0); ctx.scale(-1,1)`，且 4-4 的人脸框坐标也要同步翻转——成本高、易错，当前不做。

### 4.5 姓名输入与校验

```vue
<template>
  <div class="field">
    <label for="real-name">姓名</label>
    <input
      id="real-name"
      v-model="realName"
      type="text"
      maxlength="64"
      autocomplete="off"
      placeholder="例如：张三"
      :disabled="status === 'submitting'"
      @compositionstart="composing = true"
      @compositionend="composing = false; normalizeName()"
      @blur="normalizeName"
    >
    <p class="hint" :class="{ 'hint--error': nameLength > MAX_NAME_LEN }">
      {{ nameLength }} / {{ MAX_NAME_LEN }} 字符
      <span v-if="nameLength > MAX_NAME_LEN">（超出上限，后端将返回 1001）</span>
    </p>
  </div>
</template>
```

| 规则 | 实现 | 理由 |
|------|------|------|
| 去首尾空格 | `normalizeName()`：`realName.value = realName.value.trim()` | 防止「张三 」与「张三」被当成两个人 |
| 长度口径 | `[...name].length`（码点） | 与 Python `len(name)` 一致；`'𠮷'.length` 在 JS 是 2、Python 是 1 |
| 上界 | `MAX_NAME_LEN = 32`，输入框 `maxlength=64` 留余量 | 超长时前端即提示，不让后端 `1001` 承担校验职责 |
| 中文 IME | `compositionstart/end` 期间不 `trim`、不判长度 | 拼音输入过程中 `trim` 会打断候选词 |
| 拒绝纯空白 | `trim()` 后长度为 0 → `canSubmit=false` | 与后端 `not name.strip()` 对齐 |
| 不限制特殊字符 | 允许 `·`、`-`、英文、数字、emoji | 姓名多样性；`1004` 按原始字符串精确比较（见 `docs/03-02`） |
| 大小写 | **不做**大小写折叠 | 后端按字符串精确匹配，前端擅自折叠会出现「前端认为重复、后端认为可插入」 |

> 姓名是特征库的**唯一键**（`docs/03-04`），所以前端不做「同名自动追加」也不做「覆盖确认」，只负责把冲突清晰地交给后端 `1004` 并给出删除入口。

### 4.6 提交、回执与错误处理

```js
async function submit() {
  const name = realName.value.trim()
  if (!name) { errorText.value = '请输入姓名'; return }
  if ([...name].length > MAX_NAME_LEN) { errorText.value = `姓名最多 ${MAX_NAME_LEN} 个字符`; return }
  if (mode.value === 'upload' && !selectedFile.value) { errorText.value = '请先选择图片'; return }
  if (mode.value === 'camera' && !captured.value) { errorText.value = '请先拍照'; return }

  if (submitController) submitController.abort()       // 理论不可达（按钮已禁用），兜底
  submitController = new AbortController()
  status.value = 'submitting'
  errorText.value = ''
  notice.value = ''
  receipt.value = null
  uploadPercent.value = 0

  try {
    const options = { signal: submitController.signal }
    const res = mode.value === 'upload'
      ? await registerByImage(selectedFile.value, name, {
          ...options,
          onUploadProgress: (e) => {
            if (e.total) uploadPercent.value = Math.round((e.loaded / e.total) * 100)
          },
        })
      : await registerByFrame(name, captured.value.dataUrl, options)

    receipt.value = res.data
    notice.value = res.data.face_count > 1
      ? `检测到 ${res.data.face_count} 张人脸，已取面积最大的一张入库（record_id=${res.data.record_id}）`
      : `入库成功：${res.data.name}（record_id=${res.data.record_id}）`
    status.value = 'receipt'
    selectedFile.value = null                           // 必须重新选图才能再次提交
    releasePreview()
    captured.value = null
    camera.stop()
  } catch (err) {
    if (err.isCanceled) { status.value = 'previewing'; return }
    errorText.value = toUserMessage(err)
    status.value = 'error'
  } finally {
    submitController = null
    uploadPercent.value = 0
  }
}
```

| 场景 | 后端 `code` | `data` 关键字段 | 页面表现 |
|------|-------------|-----------------|----------|
| 单脸入库 | 0 | `record_id`、`face_count=1`、`feature_dim=512` | 绿色提示 + 回执卡 |
| 多脸入库 | 0 | `face_count>1`、`selected` 为最大脸坐标 | 黄色提示「已取最大人脸」+ 回执卡 |
| 未检测到人脸 | 1002 | — | 红字「未检测到人脸…」，保留预览可直接换图 |
| 特征提取失败 | 1003 | — | 红字，允许重试 |
| 同名已存在 | 1004 | — | 红字 + 「去特征库管理删除」链接 |
| 姓名/文件非法 | 1001 / 422 | — | 红字，指出字段 |
| 服务繁忙 / 内部错误 | 1008 / 1007 | — | 红字，建议稍后重试 |
| 网络中断 / 超时 | -1 / -2 | — | 红字 + 重试提示 |

### 4.7 摄像头与预览资源释放

资源泄漏在本页有两处：`MediaStream` 与 `objectURL`。三条路径都必须覆盖：

| 触发时机 | 需要做的事 | 代码位置 |
|----------|------------|----------|
| 切换 Tab（camera → upload） | `camera.stop()`、`captured = null` | `switchMode()` |
| 路由离开 / 组件卸载 | `camera.stop()`（`onBeforeUnmount`）、`releasePreview()` | `useCamera` + 页面 `onBeforeUnmount` |
| 重新选择图片 / 清空 | `URL.revokeObjectURL(previewUrl)` | `releasePreview()` |
| 提交成功 | 清空图片、停摄像头 | `submit()` |

```js
// FaceCollect.vue 末尾
onBeforeUnmount(() => {
  if (submitController) submitController.abort()
  camera.stop()
  releasePreview()
})

// 开发期热更新兜底：HMR 不会触发 onBeforeUnmount 的完整卸载语义
if (import.meta.hot) {
  import.meta.hot.dispose(() => {
    camera.stop()
    releasePreview()
  })
}
```

```js
// 页面隐藏（切到其他标签 / 最小化）时暂停摄像头，回来后由用户点「继续」恢复
function onVisibilityChange() {
  if (document.hidden && cameraReady.value) {
    camera.stop()
    status.value = captured.value ? 'previewing' : 'idle'
  }
}
onMounted(() => document.addEventListener('visibilitychange', onVisibilityChange))
onBeforeUnmount(() => document.removeEventListener('visibilitychange', onVisibilityChange))
```

> 不用 `<keep-alive>`（`docs/04-01` 4.6）是同一原因的另一半保障：组件被缓存时 `onBeforeUnmount` 不执行，摄像头会一直亮着。

### 4.9 性能预算

| 环节 | 目标 | 观测方式 |
|------|------|----------|
| 本地图片解码 + 压缩（4000×3000） | < 600 ms | `performance.now()` 包住 `compressImage` |
| 上传 1 MB（局域网） | < 300 ms | `onUploadProgress` 首末差值 |
| 后端处理（CPU，单脸，图 1600 长边） | 150~500 ms | 回执卡可展示 `performance.now()` 差值，或看 uvicorn 日志 |
| 摄像头开启 | < 1.5 s | 点击「开启摄像头」到 `status === 'ready'` |
| 拍照（640×480） | < 50 ms | `capture()` 同步执行 |
| 首屏（路由懒加载） | < 500 ms | Network 面板 chunk 大小 < 60 KB |

> 压缩在主线程做 canvas 绘制，4000×3000 图约 100~300 ms 白屏。可接受；若后续支持批量，再迁到 `OffscreenCanvas` + Worker。

### 4.10 可访问性与细节

- `<label for="real-name">` 与输入框绑定，Tab 可聚焦；所有按钮使用原生 `<button>`，禁用态用 `disabled` 而非仅改样式；
- 提示区加 `role="status"`（成功/普通提示）与 `role="alert"`（失败），屏幕阅读器可播报；
- `<video>` 加 `playsinline muted autoplay`，iOS Safari 不加 `playsinline` 会强制全屏；
- 文件名、尺寸、拍摄分辨率均在界面可见，避免「不知道传了哪张图」；
- 错误文案全部来自 `toUserMessage()`，后端 `message` 已含姓名与原因，前端不再二次包装。

## 七、异常点与坑点

| # | 问题 | 现象 | 定位与处置 |
|---|------|------|------------|
| 1 | **非安全上下文** | `navigator.mediaDevices` 为 `undefined`，或 `getUserMedia` 直接抛错 | 仅 `https` / `localhost` / `127.0.0.1` 可用；用局域网 IP 访问必须配 HTTPS 或改用 `localhost` 映射 |
| 2 | **权限「拒绝」被记住** | 首次点了「阻止」，之后点开启无任何反应 | 浏览器不会再次弹窗；提示用户点地址栏相机图标 → 允许，或站点设置中清除。代码里 `NotAllowedError` 文案要写清这一步 |
| 3 | **授权前枚举设备** | `enumerateDevices()` 返回 `label` 为空，下拉框全是「摄像头 1/2」 | 必须先 `getUserMedia` 成功再 `refreshDevices()`，本页 `start()` 内部已按此顺序 |
| 4 | **画面未就绪就截图** | 点「开启摄像头」后立刻拍照，得到黑图或 `null` | `capture()` 校验 `videoWidth/videoHeight`，为 0 时提示「画面尚未就绪」；拍照按钮在 `cameraReady` 前禁用 |
| 5 | **用 CSS 尺寸取像素** | 用 `video.clientWidth` 建 canvas，拍出的画面被拉伸 / 裁剪 | 必须用 `videoWidth / videoHeight`（解码分辨率），CSS 尺寸只影响显示 |
| 6 | **截图过大** | 直接用 1920×1080 + `toDataURL('image/png')`，base64 达 2~3 MB，JSON 上传慢且后端解码久 | 统一长边 640、JPEG q0.8；`registerByFrame` 走 JSON，体积直接影响延迟 |
| 7 | **摄像头被占用** | `NotReadableError: Could not start video source` | 常见于钉钉/腾讯会议/其他浏览器标签占用；关闭后重试，文案中直接点名 |
| 8 | **切 Tab 不停流** | 切到「本地图片」后摄像头指示灯仍亮，再切回报占用 | `switchMode()` 中调用 `camera.stop()`；`stop()` 必须 `track.stop()`，仅清 `srcObject` 无效 |
| 9 | **HMR 泄漏** | 改代码热更新后再开摄像头报 `NotReadableError` | `import.meta.hot.dispose()` 兜底停流；实在不行刷新整页 |
| 10 | **同文件选择不触发** | 选过一次的图片再选一次，预览不更新 | `onFileChange` 开头 `event.target.value = ''` |
| 11 | **`objectURL` 泄漏** | 反复选图后内存上涨，Blob 一直存活 | 每次替换预览前 `revokeObjectURL`，卸载时再释放一次 |
| 12 | **EXIF 方向** | 手机竖拍照片预览是横的 / 脸是躺着的 → `1002` | `createImageBitmap(file)` 默认按 EXIF 方向解码；不支持时回退 `<img>`，现代浏览器 `<img>` 也会按 EXIF 渲染 |
| 13 | **姓名长度算错** | 33 个汉字前端放行，后端返回 `1001` | 统一用 `[...name].length`；不要用 `name.length`（UTF-16 码元） |
| 14 | **IME 打断输入** | 拼音输入时被 `trim` 或截断，候选词丢失 | `compositionstart` 期间跳过 normalize，`compositionend` 后再处理 |
| 15 | **同名重复入库** | 用户连点两次「确认入库」，第二次报 `1004` | 提交中 `disabled`；成功后清空图片，从源头阻止二次提交 |
| 16 | **`1004` 无出路** | 只提示「已存在」，用户不知道去哪删 | 错误区渲染 `<RouterLink to="/library">去特征库管理</RouterLink>` |
| 17 | **多脸取错人** | 合影入库后识别不到本人 | 后端取面积最大脸；页面必须黄色提示，引导单人重采 |
| 18 | **iOS 全屏播放** | iPhone 上 `<video>` 一开就全屏，挡住表单 | 加 `playsinline muted autoplay`；`autoplay` 需 `muted` 才允许 |
