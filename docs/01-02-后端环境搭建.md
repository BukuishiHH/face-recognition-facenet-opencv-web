## 一、功能背景

本系统后端依赖横跨三个互不相容的风险点：

1. **`opencv-python` 大版本 API 断裂**——5.x 移除了 `cv2.CascadeClassifier`，而 Haar 级联人脸检测正是本系统的检测底座；
2. **`torch` 体积巨大且区分 CPU / CUDA 构建**——直接随批量依赖安装易造成长时间无反馈、下载中断；
3. **Python 解释器版本差异**——`torch`、`opencv-python` 对 3.10 / 3.11 / 3.12 的 wheel 支持范围不同。

因此环境搭建必须与业务验证解耦：先保证「可复现 + 版本正确 + 可导入」，再交由阶段 2 做业务验证。

---

## 二、开发目标

| 目标 | 说明 |
|------|------|
| 独立环境 | 使用 conda 虚拟环境 `cv_demo`（Python 3.11），与 base 环境隔离 |
| 依赖可复现 | 依赖清单固化在 `requirements.txt`，可一键重建 |
| 版本正确 | `opencv-python` 必须为 4.x 且 `cv2.CascadeClassifier` 可用 |
| 依赖可导入 | `cv2`/`numpy`/`fastapi`/`uvicorn`/`multipart`/`PIL`/`pytest` 均可成功导入 |
| 重型依赖解耦 | `torch` / `facenet-pytorch` 由人工按指导文档安装，不阻塞环境验收 |

---

## 三、功能职责

- **环境提供方**：为阶段 2 的检测 / 特征 / 存储 / 编排四大模块提供运行时；
- **风险隔离**：通过锁定 `opencv-python>=4.8,<5` 规避 API 断裂；
- **可重建保障**：任何人依据本文档 + `requirements.txt` 都能重建等价环境；
- **验证职责**：仅验证「依赖可导入 + 版本正确」，**不验证业务功能**。

## 四、功能逻辑

### 4.1 环境选型

| 项 | 取值 | 说明 |
|----|------|------|
| 环境管理 | conda | 项目实测环境，与 base 隔离，避免污染全局 |
| 环境名 | `cv_demo` | 见 `conda env list` |
| 解释器路径 | `D:\anaconda\envs\cv_demo\python.exe` | 后续所有命令均使用该绝对路径调用，规避 PATH 未激活问题 |
| Python 版本 | 3.11.17 | `torch>=2.2`、`opencv-python 4.x` 均有对应 wheel |

### 4.2 依赖分批策略

| 批次 | 依赖 | 安装方式 |
|------|------|----------|
| 批次一（核心） | `opencv-python`、`numpy`、`Pillow`、`fastapi`、`uvicorn`、`python-multipart`、`pytest`、`requests` | 本次随环境搭建批量安装 |
| 批次二（重型） | `torch`、`facenet-pytorch` | **人工安装**，指导文档：`temp/TORCH_INSTALL_GUIDE.md` |

> **分批理由**：批次二合计体积数百 MB 且需按显卡条件选择 CPU / CUDA 构建；若混在批次一，一旦网络中断会导致整个环境搭建失败并反复重装核心依赖。

### 4.3 安装逻辑

```powershell
# 0. 确认解释器
& 'D:\anaconda\envs\cv_demo\python.exe' --version

# 1. 批次一：核心依赖（注意 opencv 强制 4.x，会卸载已存在的 5.x）
& 'D:\anaconda\envs\cv_demo\python.exe' -m pip install --no-input `
    "opencv-python>=4.8,<5" numpy Pillow fastapi uvicorn python-multipart pytest requests

# 2. 批次二：人工执行，见 temp/TORCH_INSTALL_GUIDE.md
```

### 4.4 导入验证逻辑

不使用「业务跑通」作为验收，仅逐包 `import` 并打印版本，同时断言 `cv2.CascadeClassifier` 与 `cv2.data.haarcascades` 存在：

```powershell
& 'D:\anaconda\envs\cv_demo\python.exe' -c `
  "import cv2,numpy,fastapi,uvicorn,multipart,PIL,requests,pytest; `
   print(cv2.__version__, hasattr(cv2,'CascadeClassifier'))"
```

## 六、异常点与坑点

| # | 问题 | 现象 | 处置 |
|---|------|------|------|
| 1 | **`opencv-python 5.x` 不是"更新更好"** | 5.0.0 中 `cv2.CascadeClassifier` 不存在，检测模块直接崩溃 | 强制 `>=4.8,<5`，安装时自动卸载 5.x |
| 2 | `pip` 卸载/安装脚本不在 PATH | 报 `WARNING: The script xxx.exe is installed in ... which is not on PATH` | 无害警告；本项目统一使用 `python.exe -m pip` / `python.exe -m pytest` 规避 |
| 3 | PowerShell 将 pip 的 stderr 警告视为失败 | 命令 `$LASTEXITCODE = 1`，但实际 `Successfully installed` 已输出 | 判定安装结果以 `Successfully installed ...` 文本为准，而非退出码 |
| 4 | 未激活环境时 `python` 指向 base | 直接执行 `pip install` 会装进 base 而非 `cv_demo` | 一律使用绝对路径 `D:\anaconda\envs\cv_demo\python.exe -m pip` |
| 5 | `torch` 体积大、来源区分 CPU/CUDA | 直接随批量安装易超时/中断 | 拆分为批次二，人工安装 + 文档指导 |
| 6 | `numpy 2.x` 与旧版 opencv 不兼容 | 旧版 4.x 在 numpy 2 下 import 报错 | 选用 `opencv-python 4.14.x`（已适配 numpy 2）并保留 `numpy<3` 约束 |
| 7 | conda 环境中 `pip` 与 `conda` 混装 | 可能出现依赖解析冲突 | 本项目统一走 `pip`，不在 `cv_demo` 中再 `conda install` 同名包 |
| 8 | **`facenet-pytorch` 版本号误写** | 曾声明 `>=2.5.10`——PyPI 上**不存在**该版本，`pip install -r requirements.txt` 会直接报 `No matching distribution found` | 实测查询 PyPI 后修正为 `>=2.5.3`（可用：2.5.1 / 2.5.2 / 2.5.3 / 2.6.0）；**写版本号前必须先核实存在性** |
| 9 | **人脸样本忽略规则的写法陷阱** | `目录/*` 配合 `!目录/**/` 会把子目录重新纳入跟踪，导致子目录内的图片**未被忽略**（隐私图会进库） | 去掉 `!**/`，仅保留 `目录/*` + `!目录/.gitkeep`；已用 `git check-ignore -v` 实测三条路径均被正确忽略 |
| 10 | `numpy 2.x` 与部分旧依赖的 ABI 风险 | 若手动降级 numpy，torch/opencv 可能报 ABI 冲突 | 保持 `numpy 2.4.6`（opencv 4.14 已适配；torch 2.x 新版本同样支持） |
