## 一、功能背景

实时识别是 CLI `recognize_from_camera()` 的 Web 对应物。CLI 是**同步阻塞循环**：读帧 → 检测 → 比对 → 画框 → `imshow`，帧率由摄像头与 CPU 决定，天然不会重叠。浏览器必须自己调度，否则会出现三类问题：

| 问题 | CLI 中不存在 | Web 中必须处理 |
|------|--------------|----------------|
| 请求重叠 | 单线程阻塞，天然串行 | HTTP 异步，上一帧未回就发下一帧 → 请求堆积、界面延迟越来越大 |
| 帧率与推理速度不匹配 | `imshow` 跟着推理走 | 摄像头 30 fps、推理 3~10 fps，必须**丢帧**而不是排队 |
| 摄像头生命周期 | 进程退出即释放 | 路由切换、标签页隐藏、HMR 都可能留下 `MediaStream` |

因此本页的核心不是「画框」，而是**帧调度与背压控制**：

```text
摄像头 30fps ──► 采样器（每 400ms 取一帧）──► 单飞请求（in-flight ≤ 1）──► 结果覆盖层
                      ▲                              │
                      └──── 后端忙(1008)/超时(-2) ◄──┘  直接丢弃，不重试
```

| 方案 | 帧调度 | 优点 | 缺点 | 结论 |
|------|--------|------|------|------|
| `setInterval(recognize, 400)` | 固定间隔 | 写法简单 | 请求未回就叠发，弱网/CPU 下雪崩 | ✗ |
| `requestAnimationFrame` 每帧发 | 60 fps | 最流畅 | 60 QPS 直接打爆后端，必然 429 | ✗ |
| **`setTimeout` 链 + 单飞 + 自适应间隔** | 完成后再排下一次 | 天然串行、无堆积；按实测延迟调间隔 | 需自己维护循环状态 | ✅ 选用 |
| WebSocket 推流 | 服务端驱动 | 延迟最低 | 阶段 3 未提供该接口 | ✗（后续优化） |

**为什么用 `/api/recognize/frame` 而不是 `/api/recognize/image`**：帧接口走 JSON base64，实测 640×480 JPEG 约 40~80 KB，比 multipart 少一次边界解析；且后端对帧接口设计了「忙则 429 / `1008`」的快速失败语义（`docs/03-03`），正好匹配丢帧策略。

## 二、开发目标

| 目标 | 说明 |
|------|------|
| 实时预览 | 开启摄像头后 `<video>` 显示画面，页面离开自动停流 |
| 定时识别 | 默认 400 ms 采样一帧，请求完成后再排下一帧（单飞） |
| 无堆积 | 任意时刻最多 1 个在途请求；忙时丢帧并计数 |
| 自适应节流 | 若单次往返 > 800 ms，自动把间隔提到 800 ms；恢复后再降回 400 ms |
| 覆盖绘制 | 在 video 上叠加 canvas，绿框命中 / 红框未命中，标签含姓名与相似度 |
| 阈值实时生效 | 滑块调整后**下一帧**即按新阈值请求，无需重启 |
| 静默降级 | `1002`（本帧无脸）只清框不报错；`1008`/`-2` 丢帧；`-1`/`1007` 停止循环并提示 |
| 统计可见 | 已处理帧数、丢帧数、平均延迟、运行时长 |
| 暂停/继续 | 暂停只停采样，保留预览；继续立即恢复 |
| 隐私 | 不上传音频、不录屏、不落盘（`/recognize/frame` 不写标注图） |
| 资源安全 | 卸载 / 切 Tab / 隐藏页面时停流、停循环、abort 请求 |

## 三、功能职责

| 分类 | 成员 | 职责 |
|------|------|------|
| 设备 | `useCamera()` | 权限、设备选择、`capture()`、停流 |
| 循环 | `running`、`paused`、`timer` | 调度状态；`timer` 为 `setTimeout` 句柄 |
| 循环 | `tick()` | 截图 → 请求 → 更新结果 → 排下一次 |
| 参数 | `threshold`、`intervalMs` | 阈值与当前采样间隔（400 / 800 ms） |
| 结果 | `faces`、`lastMessage`、`updatedAt`、`frameSize` | 当前帧结果与元信息 |
| 统计 | `stats` | `{ frames, dropped, errors, latencySum, startedAt }` |
| 绘制 | `overlayRef` + `drawOverlay()` | 按 video 实际显示尺寸缩放绘制 |
| 方法 | `start()` / `pause()` / `resume()` / `stop()` | 生命周期 |
| 方法 | `scheduleNext(delay)` | 统一出口，避免多处 `setTimeout` 泄漏 |

**不做的事**：

- 不做录像 / 抓拍保存（需要留档请用 4-3 的「保存标注图」）；
- 不做多人跟踪 ID（后端每帧独立检测，无跟踪器，跨帧 ID 无意义）；
- 不做前端检测兜底（无脸就是无脸，不在浏览器跑检测模型）；
- 不在实时链路里弹 toast（每 400 ms 一次会刷屏，提示只放在状态栏）；
- 不做 WebSocket / WebRTC（后端未提供，见阶段 5 优化项）。

### 4.2 循环状态机

```text
        ┌────────┐  开启摄像头成功   ┌──────────┐
        │  idle  │ ────────────────► │ running  │
        └────────┘                   └──┬───┬───┘
             ▲                          │   │ 点暂停
             │ 停止                     │   ▼
             │                     ┌────┴──────┐
             │                     │  paused   │
             │                     └────┬──────┘
             │                          │ 继续
             │                          └──────► running
             │  权限失败 / -1 / 1007
             └────────────── error（显示原因 + 重试）

running 内部单帧节拍：
  tick() ──► capture() ──► recognizeByFrame() ──► drawOverlay()
     ▲                        │ 成功：interval = base
     │                        │ 慢(>800ms)：interval = 800
     └── scheduleNext() ◄─────┴ 错误：1002 清框 / 1008·-2 丢帧 / -3 静默
```

| 状态 | `running` | `paused` | `timer` | 在途请求 |
|------|-----------|----------|---------|----------|
| `idle` | false | false | null | 无 |
| `running` | true | false | 已排 | ≤ 1 |
| `paused` | false | true | null | 允许已发出的 1 个请求自然结束（结果仍绘制） |
| `error` | false | false | null | 已 abort |

> 暂停时**不 abort 在途请求**：让它把最后一帧画完，画面不会停在「有框但不知道哪一帧」的半状态；但不再排下一帧。

### 4.3 帧循环实现（单飞 + 自适应间隔）

```vue
<!-- frontend/src/views/CameraRealTime.vue（调度核心） -->
<script setup>
import { computed, onBeforeUnmount, onMounted, ref } from 'vue'
import {
  DEFAULT_THRESHOLD, THRESHOLD_MAX, THRESHOLD_MIN, recognizeByFrame,
} from '../api/face'
import { useCamera } from '../composables/useCamera'
import { drawFaceBoxes } from '../utils/draw'
import { toUserMessage } from '../utils/errors'

const BASE_INTERVAL = 400        // 基础采样间隔（ms）
const MAX_INTERVAL = 800         // 慢链路下的上限，再慢就说明后端过载
const SLOW_RTT = 800             // 超过此往返时间判定为慢

const camera = useCamera({ width: 640, height: 480 })
const { videoRef } = camera
const overlayRef = ref(null)

const running = ref(false)
const paused = ref(false)
const starting = ref(false)
const threshold = ref(DEFAULT_THRESHOLD)
const intervalMs = ref(BASE_INTERVAL)
const faces = ref([])
const errorText = ref('')
const lastMessage = ref('')
const updatedAt = ref('')
const nowTick = ref(Date.now())
const frameSize = ref({ width: 0, height: 0 })   // 最近一次送入后端的帧像素尺寸
const stats = ref({ frames: 0, dropped: 0, errors: 0, latencySum: 0, startedAt: 0 })

let timer = null
let controller = null

const avgLatency = computed(() =>
  stats.value.frames ? Math.round(stats.value.latencySum / stats.value.frames) : 0)
const uptime = computed(() => {
  if (!stats.value.startedAt) return '00:00'
  const sec = Math.max(0, Math.floor((nowTick.value - stats.value.startedAt) / 1000))
  return `${String(Math.floor(sec / 60)).padStart(2, '0')}:${String(sec % 60).padStart(2, '0')}`
})

/** 唯一排程出口：清旧 timer 再排新，避免多处 setTimeout 泄漏 */
function scheduleNext(delay = intervalMs.value) {
  clearTimeout(timer)
  timer = null
  if (!running.value || paused.value) return
  timer = setTimeout(tick, delay)
}

async function tick() {
  if (!running.value || paused.value) return
  const shot = camera.capture({ maxWidth: 640, quality: 0.8 })
  if (!shot) { scheduleNext(200); return }        // 首帧未就绪，稍后再试
  frameSize.value = { width: shot.width, height: shot.height }

  controller = new AbortController()
  const startedAt = performance.now()
  try {
    const res = await recognizeByFrame(shot.dataUrl, {
      threshold: Number(threshold.value),
      signal: controller.signal,
    })
    if (!running.value) return                   // 请求返回时已被停止
    const latency = Math.round(performance.now() - startedAt)
    stats.value.frames += 1
    stats.value.latencySum += latency
    faces.value = res.data.faces
    lastMessage.value = res.data.library_empty
      ? '特征库为空，请先到「人脸采集」录入'
      : res.message
    updatedAt.value = new Date().toLocaleTimeString('zh-CN', { hour12: false })
    nowTick.value = Date.now()
    drawOverlay()
    intervalMs.value = latency > SLOW_RTT ? MAX_INTERVAL : BASE_INTERVAL
  } catch (err) {
    if (err.isCanceled) return
    if (err.code === 1002) {                     // 本帧无脸：清框，不报错
      faces.value = []
      lastMessage.value = '当前画面未检测到人脸'
      drawOverlay()
    } else if (err.code === 1008 || err.code === -2) {
      stats.value.dropped += 1                   // 后端忙 / 超时：直接丢帧
      lastMessage.value = err.code === 1008 ? '推理繁忙，已丢帧' : '本帧超时，已丢帧'
    } else if (err.code === -1 || err.code === 1001 || err.code === 1007) {
      fail(err)                                  // 环境级错误：停止循环
      return
    } else {
      stats.value.errors += 1
      lastMessage.value = toUserMessage(err)
    }
  } finally {
    controller = null
    if (running.value && !paused.value) scheduleNext()
  }
}

function fail(err) {
  running.value = false
  paused.value = false
  clearTimeout(timer)
  timer = null
  if (controller) { controller.abort(); controller = null }
  faces.value = []
  errorText.value = toUserMessage(err)
  camera.stop()
  drawOverlay()
}
</script>
```

| 参数 | 取值 | 依据 |
|------|------|------|
| 基础间隔 400 ms | 2.5 QPS | CPU 下单帧 150~500 ms，留出串行余量；人眼看标签切换无明显停顿 |
| 慢阈值 800 ms | `MAX_INTERVAL` | 超过后继续 2.5 QPS 只会让队列变长，降频是唯一正确选择 |
| 丢帧条件 | `1008` / `-2` | 后端语义就是「忙/超时，别等」，重试只会加剧拥塞 |
| 停止条件 | `-1` / `1007` / `1001` | 网络断、服务崩、参数非法，继续循环毫无意义 |
| 无脸 `1002` | 清框 + 状态栏文案 | 用户移开脸时不应看到红色报错 |

> **为什么不是 `setInterval`**：`setInterval(tick, 400)` 在 tick 内 `await` 时仍会每 400 ms 触发一次，弱网下并发请求数等于延迟/400，10 个请求同时压后端必然 `1008`。`setTimeout` 链 + `finally` 排下一次，保证任意时刻只有 0 或 1 个在途请求。


### 4.4 覆盖层绘制（`utils/draw.js`）

4-3 的 `FaceCanvas.vue` 面向「静态图 + 框」，内部 `draw()` 直接遍历 `faces` 绘制；4-4 是「video + 覆盖层」，生命周期不同（要按识别结果反复重绘、要处理 `frameSize` 缩放），因此**不复用组件**，而是把绘制规则抽成纯函数 `drawFaceBoxes()`，两页视觉对齐（同为 DPR `setTransform`、2px 描边、绿/红 + 标签底色）。

> 可选重构：把 `FaceCanvas.vue` 内的 `for` 循环替换为调用 `drawFaceBoxes()`，两页真正共用一份绘制代码。不改也能正常工作，只要颜色/字号/标签位置保持一致（本页与 4-3 的表格逐项对齐即可）。

```js
// frontend/src/utils/draw.js
/**
 * 在 canvas 2d 上下文里绘制人脸框与标签
 * @param {CanvasRenderingContext2D} ctx  已按 DPR setTransform
 * @param {Array} faces [{ box:{x,y,w,h}, name, similarity, matched }]
 * @param {number} scale 原图坐标 → 画布 CSS 像素的比例
 */
export function drawFaceBoxes(ctx, faces, scale, { activeIndex = -1, showLabels = true } = {}) {
  faces.forEach((face, index) => {
    const { x, y, w, h } = face.box
    const color = face.matched ? '#16a34a' : '#dc2626'
    ctx.lineWidth = index === activeIndex ? 4 : 2
    ctx.strokeStyle = color
    ctx.strokeRect(x * scale, y * scale, w * scale, h * scale)
    if (!showLabels) return
    const label = face.matched
      ? `${face.name} ${(face.similarity * 100).toFixed(1)}%`
      : `未知 ${(face.similarity * 100).toFixed(1)}%`
    ctx.font = '13px system-ui, -apple-system, "Segoe UI", sans-serif'
    const tagW = ctx.measureText(label).width + 8
    const tagH = 20
    const top = y * scale
    const tagTop = top - tagH >= 0 ? top - tagH : top
    ctx.fillStyle = color
    ctx.fillRect(x * scale, tagTop, tagW, tagH)
    ctx.fillStyle = '#fff'
    ctx.textBaseline = 'middle'
    ctx.fillText(label, x * scale + 4, tagTop + tagH / 2)
  })
}
```

```js
// CameraRealTime.vue 续：覆盖层尺寸与视频显示尺寸严格一致
const canvasSize = ref({ width: 0, height: 0 })

function drawOverlay() {
  const canvas = overlayRef.value
  const video = videoRef.value
  if (!canvas || !video || !video.videoWidth) return
  const rect = video.getBoundingClientRect()
  if (!rect.width || !rect.height) return
  const dpr = window.devicePixelRatio || 1
  canvas.width = Math.round(rect.width * dpr)
  canvas.height = Math.round(rect.height * dpr)
  canvas.style.width = `${rect.width}px`
  canvas.style.height = `${rect.height}px`
  canvasSize.value = { width: Math.round(rect.width), height: Math.round(rect.height) }

  const ctx = canvas.getContext('2d')
  ctx.setTransform(dpr, 0, 0, dpr, 0, 0)
  ctx.clearRect(0, 0, rect.width, rect.height)
  // 框坐标属于「送检帧」坐标系（capture 可能把 1280 缩到 640），不是 videoWidth
  const srcWidth = frameSize.value.width || video.videoWidth
  drawFaceBoxes(ctx, faces.value, rect.width / srcWidth)
}

let resizeObserver = null
onMounted(() => {
  // 容器尺寸变化（窗口缩放 / 侧栏折叠）时重绘，避免框与画面错位
  if (videoRef.value && typeof ResizeObserver !== 'undefined') {
    resizeObserver = new ResizeObserver(() => drawOverlay())
    resizeObserver.observe(videoRef.value)
  }
})
```

| 绘制要素 | 取值 | 说明 |
|----------|------|------|
| 坐标系 | `frameSize.width`（送检帧）→ `rect.width` | 与 4-3 同理；`capture()` 会把长边压到 640，若用 `videoWidth` 算比例，1280 宽设备上框会小一半 |
| CSS 尺寸 | 与 `<video>` 完全一致 | 容器 `position:relative`，video `display:block; width:100%; height:auto`（**不写死宽高比、不用 `object-fit`**），canvas `position:absolute; inset:0`；这样 `rect` 就是视频显示区域，无留白也无拉伸 |
| 更新频率 | 每帧识别结果返回时 | 不随视频帧刷新，标签 2.5 次/秒更新属预期 |
| 清空时机 | `1002` / 停止 / 失败 | `ctx.clearRect` 后不重绘，避免残影 |

> **不要给 `<video>` 叠加 CSS `transform: scaleX(-1)` 做镜像**：视频镜像了但 canvas 坐标没镜像，框会左右颠倒。采集页（4-2）与实时页统一不镜像。

### 4.5 生命周期：开启 / 暂停 / 继续 / 停止

```js
async function start() {
  if (starting.value || running.value) return
  starting.value = true
  errorText.value = ''
  lastMessage.value = '正在请求摄像头权限…'
  const ok = await camera.start(camera.activeDeviceId.value)
  starting.value = false
  if (!ok) {
    errorText.value = camera.errorText.value
    lastMessage.value = ''
    return
  }
  stats.value = { frames: 0, dropped: 0, errors: 0, latencySum: 0, startedAt: Date.now() }
  nowTick.value = Date.now()
  faces.value = []
  intervalMs.value = BASE_INTERVAL
  running.value = true
  paused.value = false
  lastMessage.value = '已开启，正在识别…'
  timer = setTimeout(tick, 300)        // 等首帧稳定后再截
}

function pause() {
  if (!running.value || paused.value) return
  paused.value = true
  clearTimeout(timer)
  timer = null
  lastMessage.value = '已暂停（画面保留，最后一帧结果保留）'
}

function resume() {
  if (!running.value || !paused.value) return
  paused.value = false
  lastMessage.value = '已继续'
  scheduleNext(0)                      // 立即识别一帧，不等 400ms
}

function stop() {
  running.value = false
  paused.value = false
  clearTimeout(timer)
  timer = null
  if (controller) { controller.abort(); controller = null }
  camera.stop()
  faces.value = []
  lastMessage.value = ''
  updatedAt.value = ''
  intervalMs.value = BASE_INTERVAL
  drawOverlay()
}

/** 标签页隐藏时自动暂停，避免后台空转烧 CPU */
function onVisibilityChange() {
  if (document.hidden && running.value && !paused.value) {
    pause()
    lastMessage.value = '页面已切到后台，识别自动暂停'
  }
}

onMounted(() => document.addEventListener('visibilitychange', onVisibilityChange))
onBeforeUnmount(() => {
  document.removeEventListener('visibilitychange', onVisibilityChange)
  if (resizeObserver) { resizeObserver.disconnect(); resizeObserver = null }
  stop()
})

// HMR 兜底：热更新不会触发完整卸载
if (import.meta.hot) {
  import.meta.hot.dispose(() => stop())
}
```

```vue
<template>
  <div class="viewer">
    <video ref="videoRef" class="viewer__video" autoplay playsinline muted />
    <canvas ref="overlayRef" class="viewer__overlay" />
    <div v-if="!running && !starting" class="viewer__placeholder">
      点击「开启摄像头」开始实时识别
    </div>
  </div>

  <div class="controls">
    <button v-if="!running" class="btn btn--primary" :disabled="starting" @click="start">
      {{ starting ? '正在开启…' : '开启摄像头' }}
    </button>
    <template v-else>
      <button class="btn" @click="paused ? resume() : pause()">
        {{ paused ? '继续' : '暂停' }}
      </button>
      <button class="btn btn--danger" @click="stop">停止</button>
    </template>
  </div>
</template>
```

| 动作 | 摄像头 | 循环 | 覆盖层 | 统计 |
|------|--------|------|--------|------|
| `start()` | 申请并播放 | 300 ms 后首帧 | 清空 | 重置 |
| `pause()` | 保持 | 停排程，允许 1 个在途完成 | 保留 | 冻结 |
| `resume()` | 保持 | 立即 tick | 保留到新结果 | 继续累加 |
| `stop()` | `track.stop()` | 停排程 + abort | 清空 | 保留（便于回看） |
| 路由离开 | 同 `stop()` | 同 `stop()` | — | — |
| 标签页隐藏 | 保持（不黑屏） | 自动 `pause()` | 保留 | 冻结 |

> 隐藏页面**不停止摄像头**：`visibilitychange` 只暂停循环。如果连流一起停，用户切回来时 `video` 是黑屏且不会自动恢复，需要再点一次「开启」——体验更差。若产品对隐私要求更高，可改为 `stop()`，但必须在恢复时重新 `start()`。

### 4.6 错误分级与用户提示

| 场景 | 来源 | `code` | 处理 | 用户看到 |
|------|------|--------|------|----------|
| 无摄像头 / 无权限 | `getUserMedia` 失败 | — | 不进循环，展示重试 | 「无法访问摄像头：NotAllowedError」+「重试」 |
| 摄像头被占用 | `NotReadableError` | — | 同上 | 「摄像头被其他程序占用」 |
| 本帧无脸 | 后端 | `1002` | 清框，继续循环 | 状态栏「当前画面未检测到人脸」（灰色） |
| 后端忙 | 后端 | `1008`（HTTP 429） | 丢帧，继续 | 状态栏「推理繁忙，已丢帧」 |
| 请求超时 | axios | `-2` | 丢帧，继续 | 状态栏「本帧超时，已丢帧」 |
| 请求被 abort | axios | `-1` 或 `err.isCanceled` | 忽略 | 无（`CanceledError` 不进统计） |
| 特征库为空 | 后端 `library_empty:true` | `0` | 正常绘制（全红框） | 状态栏「特征库为空，请先到「人脸采集」录入」 |
| 服务不可达 | axios | `-1` | 停止循环 + 停流 | 「无法连接后端服务…」+「重试」 |
| 阈值非法 | 后端 | `1001` | 停止循环 | 「threshold 必须在 0.3~0.95 之间」（滑块已限位，理论不会触发） |
| 图片/帧非法 | 后端 | `1001` | 停止循环 | 「图像数据不合法」 |
| 服务端异常 | 后端 | `1007`（HTTP 200 或 500） | 计数 + 状态栏 | 「服务器内部错误」 |
| 特征提取失败 | 后端 | `1003` | 计数 + 状态栏 | 「特征提取失败，请重试」 |

```js
// 状态栏渲染：按消息类型着色，不做 toast
const messageTone = computed(() => {
  if (errorText.value) return 'danger'
  if (!lastMessage.value) return 'muted'
  if (lastMessage.value.includes('丢帧') || lastMessage.value.includes('超时')) return 'warn'
  if (lastMessage.value.includes('未检测到') || lastMessage.value.includes('特征库为空')) return 'muted'
  return 'ok'
})
```

```vue
<p class="statusbar" :class="`statusbar--${messageTone}`">
  <span v-if="errorText">{{ errorText }}</span>
  <span v-else>{{ lastMessage || '待开启' }}</span>
  <span v-if="updatedAt" class="statusbar__time">· 更新于 {{ updatedAt }}</span>
</p>
```

| 决策 | 理由 |
|------|------|
| 实时链路零 toast | 2.5 次/秒的提示会覆盖整个屏幕，用户无法关闭 |
| `1008`/`-2` 不重试 | 重试加剧拥塞；下一拍自然会再试 |
| `-3` 静默 | 后端已记录日志，前端无信息可补充 |
| `1002` 不清空统计 | 无脸是正常状态，不是错误 |
| 错误态显示「重试」 | 错误态下唯一有效的动作就是重新 `start()`，不用回主页 |

### 4.8 与 4-3 图片识别页的一致性

## 七、异常点与坑点

| # | 坑点 | 现象 | 处理 |
|---|------|------|------|
| 1 | 用 `setInterval` 驱动 | 弱网下并发请求堆积，`1008` 连发，界面越用越慢 | `setTimeout` 链 + `finally` 排程（4.3） |
| 2 | `finally` 里排程但 `catch` 里已 `return` | 停止后仍排一次 `tick`，摄像头灯复亮 | `scheduleNext` 内部判 `running && !paused`（4.3） |
| 3 | 停止时只清 timer 不 abort | 在途请求回来后把 `faces` 写回，已停止的页面又出现框 | `stop()`/`fail()` 都 `controller.abort()`，且 `tick` 回填前判 `running` |
| 4 | 用 `videoWidth` 算缩放 | 1280 宽摄像头时框只有真实一半大小 | 用 `frameSize.width`（送检帧尺寸） |
| 5 | 给 video 加 `scaleX(-1)` | 画面镜像、框不镜像，左右颠倒 | 统一不镜像 |
| 6 | canvas 尺寸用 CSS 百分比但不设 `width/height` 属性 | 高 DPI 下模糊、坐标漂移 | `canvas.width = rect.width * dpr` + `setTransform(dpr,...)` |
| 7 | 忽略 `video.getBoundingClientRect()` 为 0 | 首帧时容器未布局，`scale = Infinity`，框消失 | 尺寸为 0 直接返回，等 `ResizeObserver` 触发 |
| 8 | `drawOverlay` 依赖 `videoWidth` 就绪 | 开启瞬间绘制被跳过，第一帧无框 | 由识别结果返回时机驱动绘制，不在 `onMounted` 直接画 |
| 9 | 把 `CanceledError` 计入 `errors` | 每次停止都报一次「网络错误」 | `err.isCanceled` 优先判断并直接 `return` |
| 10 | `finally` 里也排程 + `catch` 里又排程 | 一次失败排出两条定时链，请求数翻倍 | 排程只在 `finally` 一处 |
| 11 | 暂停时 abort 在途请求 | 结果丢失，画面停在旧框上但状态显示已暂停，看不出新旧 | 暂停只停排程（4.2 表下注释） |
| 12 | 标签页隐藏时停流 | 切回时 video 黑屏，需手动重开 | 隐藏仅 `pause()`，不停流 |
| 13 | HMR 期间旧实例未清 | 改代码后出现两路 `getUserMedia`，摄像头被自己占用 | `import.meta.hot.dispose(() => stop())` |
| 14 | 循环里读响应式 `threshold` 但没 `Number()` | `input type=range` 绑定值为字符串，`0.6` 变 `"0.6"`，后端 422 | `Number(threshold.value)` |
| 15 | 阈值滑块 `step` 太小 | 每帧都因滑块微调触发重渲染 | `step="0.05"`，且修改阈值不重置循环 |
| 16 | 统计用局部变量而非 `ref` | 面板数字不变（非响应式） | `stats` 用 `ref`，整体替换或逐字段累加均可 |
| 17 | `uptime` 只在识别成功时更新 | 10 s 不动时运行时长停滞 | 独立 1 s 心跳更新 `nowTick` |
| 18 | 忘记 `muted` / `playsinline` | 部分浏览器自动播放被拦，`play()` 报 NotAllowedError；iOS 全屏播放 | `autoplay muted playsinline` 三件套 |
