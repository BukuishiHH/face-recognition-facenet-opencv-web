## 一、功能背景

后端在 `docs/03-04` 提供了两个库管理接口，对应 CLI `face_db.py` 的 `list_people()` 与 `delete_person()`：

| 能力 | CLI | HTTP | 说明 |
|------|-----|------|------|
| 查看全部 | `show_all_features()` 打印 `[{id, name}]` | `GET /api/face/library` | 返回 `total` + `items[{id,name,timestamp,feature_dim}]` |
| 按姓名删除 | `db.delete_by_name(name)` | `DELETE /api/face/library?name=` | 一次删掉该姓名**全部**特征，返回 `{name, deleted}` |

库里存的是「一行 = 一条 512 维特征」，而用户心里想的是「一个人」。因此本页的关键是**聚合展示 + 精确删除**：

```text
GET /api/face/library
{ "code": 0, "message": "共 3 条特征记录",
  "data": { "total": 3, "items": [
      { "id": 1, "name": "丁真", "timestamp": "2026-10-18 15:02:11", "feature_dim": 512 },
      { "id": 2, "name": "丁真", "timestamp": "2026-10-18 15:03:47", "feature_dim": 512 },
      { "id": 3, "name": "测试用户A", "timestamp": "2026-10-18 16:20:05", "feature_dim": 512 } ] } }
        │
        ├─ 视图 A「按人」：以 name 聚合，显示 条数/维度/最近录入时间
        └─ 视图 B「明细」：逐条特征，显示 id/name/timestamp/feature_dim
```

| 删除语义 | 说明 | 前端处理 |
|----------|------|----------|
| 按姓名 | 该姓名下所有特征全删 | 二次确认写明「将删除 N 条特征」，N 取聚合结果 |
| 按 id | 阶段 3 未提供 | 不做（明细视图也不给单条删除按钮，避免用户误以为能删单条） |

## 二、开发目标

| 目标 | 说明 |
|------|------|
| 一键加载 | 进入页面自动 `GET /api/face/library`，无需手动点刷新 |
| 双视图 | 「按人」/「明细」切换，同一份数据两种呈现，前端聚合 |
| 搜索过滤 | 姓名子串匹配，纯前端过滤，不发请求 |
| 精确删除 | 仅按姓名删除，原生 `<dialog>` 二次确认，展示将被删除的条数 |
| 删除即刷新 | 删除成功后重新拉取列表，不做本地删除推断（后端可能有并发写入） |
| 空态友好 | 库为空 → 引导去「人脸采集」；搜索无结果 → 提示清空搜索词 |
| 维度自检 | 任一条特征 `feature_dim !== 512` → 顶部黄条告警（模型不匹配） |
| 错误可读 | `-1`/`-2`/`1007` 显示重试按钮；`1005`（记录不存在）视为「已不存在」直接刷新 |
| 只读兜底 | 列表加载失败时删除入口禁用，避免对未知数据执行破坏性操作 |
| 规模可用 | 200 人规模下首屏渲染 < 300 ms（不分页，超出再加） |
| 可访问性 | 表格有 caption、按钮有 `aria-label`、对话框用原生语义 |

## 三、功能职责

| 分类 | 成员 | 职责 |
|------|------|------|
| 数据 | `items` | `GET /api/face/library` 的 `data.items`（逐条记录，`id ASC`） |
| 数据 | `people` | `computed` 聚合结果：`{ name, count, dims, latest, ids }` |
| 数据 | `filteredPeople` / `filteredItems` | 搜索过滤后的视图数据 |
| 状态 | `loading` / `errorText` / `loadedAt` | 加载态与错误态 |
| 状态 | `view` | `'people' \| 'items'` |
| 状态 | `keyword` | 搜索关键词（`v-model`，`trim` 后比较） |
| 删除 | `pendingName` / `dialogRef` / `deleting` | 待删除姓名与确认对话框 |
| 方法 | `load()` | 拉取列表，`finally` 复位 `loading` |
| 方法 | `askDelete(name)` / `confirmDelete()` / `cancelDelete()` | 删除三步 |
| 方法 | `openDialog()` / `closeDialog()` | 原生 dialog 的显示与关闭 |
| 展示 | `dimWarning` | 是否存在非 512 维特征 |

**不做的事**：

- 不做分页（200 人以内一屏足够；超过 500 条再引入分页或虚拟滚动）；
- 不做批量勾选删除（按姓名删除已是「一次删一个人」，勾选反而增加误删风险）；
- 不做编辑/重命名（后端未提供，重命名等价于「删除 + 重新采集」）；
- 不在本页做采图/上传（那是 4-2 的职责）；
- 不做特征向量可视化（512 维无法直观呈现，且涉及隐私）。

| 元素 | 数据来源 | 备注 |
|------|----------|------|
| 头部计数 | `items.length` / `people.length` | 「共 N 条 / M 人」 |
| 维度告警条 | `dimWarning` | 仅在有异常维度时出现 |
| 视图切换 | `view` | 两个 `button`，用 `aria-pressed` 表示选中 |
| 搜索框 | `keyword` | `placeholder="按姓名筛选"`，输入即过滤 |
| 表格 | `filtered*` | 按人视图 5 列，明细视图 4 列 |
| 更新时间 | `loadedAt` | 每次 `load()` 成功后刷新 |

### 4.2 数据映射与按人聚合

```js
// frontend/src/views/FaceLibrary.vue
import { computed, onMounted, ref } from 'vue'
import { deleteLibraryItem, getLibrary } from '../api/face'
import { toUserMessage } from '../utils/errors'

const EXPECTED_FEATURE_DIM = 512   // 与 backend/facenet_encoder.py 的 EMBEDDING_DIM 一致

const items = ref([])              // GET /api/face/library → data.items
const loading = ref(false)
const deleting = ref(false)
const errorText = ref('')
const loadedAt = ref('')
const keyword = ref('')
const view = ref('people')
const pendingName = ref('')
const pendingCount = ref(0)
const dialogRef = ref(null)
const notice = ref('')            // 删除成功等一次性提示（绿色条，可手动关闭）

/** 逐条记录 → 按人聚合（同一姓名多条特征） */
const people = computed(() => {
  const map = new Map()
  items.value.forEach((rec) => {
    const person = map.get(rec.name) || {
      name: rec.name, count: 0, dims: new Set(), latest: '', ids: [],
    }
    person.count += 1
    person.dims.add(rec.feature_dim)
    person.ids.push(rec.id)
    // timestamp 形如 "2026-10-18 15:02:11"，字符串比较即可定位最新
    if (rec.timestamp > person.latest) person.latest = rec.timestamp
    map.set(rec.name, person)
  })
  return [...map.values()]
    .map((person) => ({ ...person, dims: [...person.dims].sort((a, b) => a - b) }))
    .sort((a, b) => a.name.localeCompare(b.name, 'zh-CN'))
})

const kw = computed(() => keyword.value.trim().toLowerCase())
const filteredPeople = computed(() =>
  kw.value ? people.value.filter((p) => p.name.toLowerCase().includes(kw.value)) : people.value)
const filteredItems = computed(() =>
  kw.value ? items.value.filter((r) => r.name.toLowerCase().includes(kw.value)) : items.value)

const dimWarning = computed(() => {
  const bad = items.value.filter((r) => r.feature_dim !== EXPECTED_FEATURE_DIM)
  return bad.length
    ? `检测到 ${bad.length} 条非 ${EXPECTED_FEATURE_DIM} 维特征，可能使用了其他模型`
    : ''
})
```

| 后端字段 | 前端用法 | 注意 |
|----------|----------|------|
| `id` | 明细视图行号、`:key`、聚合里的 `ids` | 自增主键，唯一；列表按 `id ASC` |
| `name` | 聚合键、删除参数 | 后端已 `strip()`，长度 1~32 |
| `timestamp` | 「最近录入」列 | SQLite `CURRENT_TIMESTAMP`（UTC），仅用于排序与展示 |
| `feature_dim` | 维度列 + 告警判定 | 每条独立值，聚合时用 `Set` |

> **`timestamp` 是 UTC**：SQLite `CURRENT_TIMESTAMP` 返回 UTC 时间（如 `2026-10-18 15:02:11` 对应北京时间 23:02）。阶段 4 直接展示原值并在表头标注「(UTC)」，避免用户按本地时间误读；要转换需在前端补 `Z`（`new Date(rec.timestamp.replace(' ', 'T') + 'Z')`）。
>
> **字段名必须是 `feature_dim` / `timestamp`**，不是 `dim` / `created_at`：`docs/03-04` 的 `list_records()` 只返回这四个字段，取错名会导致维度列全空、时间列全 `undefined`。

### 4.3 列表加载与刷新

```js
async function load() {
  if (loading.value) return            // 防止连点刷新造成并发
  loading.value = true
  errorText.value = ''
  notice.value = ''
  try {
    const res = await getLibrary()     // 已解包：{ code, message, data }
    items.value = res.data.items || [] // 字段是 items，不是 records
    loadedAt.value = new Date().toLocaleTimeString('zh-CN', { hour12: false })
  } catch (err) {
    errorText.value = toUserMessage(err)
    items.value = []                   // 失败清空，避免显示过期数据 + 可点删除
  } finally {
    loading.value = false
  }
}

onMounted(load)
```

| 场景 | 行为 | 理由 |
|------|------|------|
| 首次进入 | `onMounted(load)` | 页面即数据，无需点按钮 |
| 点「刷新」 | `load()`（`loading` 时直接返回） | 连点不产生并发请求 |
| 删除成功后 | `await load()` | 以后端为准，不做本地过滤推断 |
| 加载失败 | 清空 `items` + 展示重试 | 不能让用户对「过期的列表」执行删除 |
| 空库 | 空态引导，`errorText` 为空 | `docs/03-04` 空库返回 `code=0, total=0, items=[]`，不是错误 |
| 路由离开后返回 | 重新挂载 → 重新 `load()` | 路由禁用 `<keep-alive>`（`docs/04-01`），无需手动失效 |

> 请求函数直接复用 `docs/04-01` 已定义的 `getLibrary()`（`GET /face/library`）与 `deleteLibraryItem(name)`（`DELETE /face/library?name=`），**本页不新增 API 封装**。axios 的 `params` 会自动做 URL 编码，无需手写 `encodeURIComponent`。
>
> 不使用 `watch(keyword, load)`：搜索是纯前端过滤，不应触发任何请求。若误加，每敲一个字就 GET 一次，200 人库也扛得住但毫无意义且会打断输入。规模 > 1000 条需服务端搜索时再改（阶段 5）。

### 4.4 按姓名删除流程（原生 `<dialog>`）

```js
function askDelete(person) {
  if (loading.value || errorText.value) return   // 数据不可信时禁止删除
  pendingName.value = person.name
  pendingCount.value = person.count
  dialogRef.value?.showModal()                   // 原生模态：焦点陷阱 + ESC + ::backdrop
}

function cancelDelete() {
  dialogRef.value?.close()
  pendingName.value = ''
  pendingCount.value = 0
}

async function confirmDelete() {
  if (!pendingName.value || deleting.value) return
  deleting.value = true
  try {
    const res = await deleteLibraryItem(pendingName.value)   // DELETE /face/library?name=
    dialogRef.value?.close()
    const removed = res.data.deleted ?? pendingCount.value
    notice.value = `已删除「${pendingName.value}」的 ${removed} 条特征`
    pendingName.value = ''
    pendingCount.value = 0
    await load()                                 // 以后端为准刷新
  } catch (err) {
    if (err.code === 1005) {
      // 已被别处删除（后端删除 0 行 → 1005）：关窗 + 刷新，不报红
      dialogRef.value?.close()
      pendingName.value = ''
      notice.value = '该用户已不存在，列表已刷新'
      await load()
    } else if (err.code === 1001) {
      notice.value = '姓名参数不合法，请刷新后重试'
    } else {
      errorText.value = toUserMessage(err)
    }
  } finally {
    deleting.value = false
  }
}
```

```vue
<dialog ref="dialogRef" class="confirm" @close="cancelDelete">
  <form method="dialog" @submit.prevent>
    <h2>删除确认</h2>
    <p>将删除「{{ pendingName }}」的 {{ pendingCount }} 条特征，此操作不可撤销。</p>
    <menu>
      <button type="button" class="btn" @click="cancelDelete">取消</button>
      <button type="button" class="btn btn--danger" :disabled="deleting" @click="confirmDelete">
        {{ deleting ? '删除中…' : '删除' }}
      </button>
    </menu>
  </form>
</dialog>
```

| 决策 | 说明 |
|------|------|
| 原生 `<dialog>` + `showModal()` | 焦点陷阱、ESC 关闭、`::backdrop` 全部由浏览器提供；自绘遮罩要手写 3 件事且易出 bug |
| 确认文案带条数 | 「张三 有 2 条特征」，用户能感知影响范围；按姓名删除会一次删光 |
| 删除按钮不在表格里直接生效 | 表格里的 `[删除]` 只负责 `askDelete()`，误点最多弹出对话框 |
| 成功后 `await load()` | 后端可能在删除瞬间有并发写入（另一人正在采集），本地推断会偏差 |
| `1005` 当成功处理 | 目标已不存在，用户的意图已达成；报错反而困惑（HTTP 仍是 200 + `code=1005`） |
| 失败不关窗 | 保留上下文，用户可重试或取消（`errorText` 置位后 `askDelete` 会拒绝再次进入） |
| 不使用 `confirm()` | 阻塞主线程、无法定制样式、移动端表现差 |

| 交互 | 实现 | 说明 |
|------|------|------|
| 视图切换 | 两个 `button` + `aria-pressed` | 不用 `<select>`：只有两个选项，切换成本更低 |
| 搜索 | `v-model="keyword"` + `computed` 过滤 | 大小写不敏感、`trim` 后为空则不过滤 |
| 排序 | 按人视图 `localeCompare('zh-CN')`；明细沿用后端 `id ASC`（录入先后） | 中文按拼音，符合中文用户预期；明细顺序稳定不跳动 |
| 空结果 | 搜索无命中显示「没有匹配的用户」+「清空搜索」 | 与「库为空」区分开来 |
| 维度列 | 聚合后可能出现 `512 / 128` | 同一人混入不同模型的特征时必须暴露，而非取第一条 |
| 明细视图无删除 | 按姓名删除语义下，行级删除会误导 | 详见 4.4 |

### 4.6 空态、错误态与维度告警

```vue
<p v-if="notice" class="banner banner--ok">
  {{ notice }} <button class="link" @click="notice = ''">知道了</button>
</p>
<p v-if="dimWarning" class="banner banner--warn">⚠ {{ dimWarning }}</p>

<div v-if="errorText" class="state state--error">
  <p>{{ errorText }}</p>
  <button class="btn" @click="load">重试</button>
</div>

<div v-else-if="loading && !items.length" class="state">正在加载特征库…</div>

<div v-else-if="!items.length" class="state state--empty">
  <p>特征库还是空的。</p>
  <RouterLink class="btn btn--primary" to="/collect">去录入第一张人脸</RouterLink>
</div>

<div v-else-if="!(view === 'people' ? filteredPeople : filteredItems).length" class="state">
  <p>没有匹配「{{ keyword }}」的用户。</p>
  <button class="link" @click="keyword = ''">清空搜索</button>
</div>
```

| 状态 | 触发条件 | 展示 | 删除入口 |
|------|----------|------|----------|
| 首次加载 | `loading && !items.length` | 骨架/文案 | 不可见 |
| 空库 | `!loading && !errorText && !items.length` | 引导去采集 | 不可见 |
| 搜索无结果 | 有数据但过滤后为空 | 提示 + 清空搜索 | 不可见 |
| 加载失败 | `errorText` 非空 | 错误文案 + 重试 | 禁用（`askDelete` 内也拦） |
| 维度异常 | 任一条 `feature_dim !== 512` | 顶部黄条 | 正常可用 |
| 删除成功 | `notice` 非空 | 绿色条 | 正常可用 |

> 维度告警**不阻塞**操作：老库可能混入 128 维（换过模型），用户仍需要能删掉它。但告警必须显眼，否则识别时该人员「永远匹配不上」而用户无从得知原因。

### 4.7 与 CLI / 存储层的一致性

| 行为 | CLI / `db_utils` | 本页 | 一致性 |
|------|-----------------|------|--------|
| 列出全部 | `show_all_features()` → `get_all_features()` 只给 `id/name` | 明细视图 `id/name/feature_dim/timestamp` | ✅ 数据同源；本页走 `list_records()`（不读 BLOB） |
| 按人查看 | 无（需自己 `groupby`） | 按人视图聚合 | ➕ 增强 |
| 删除 | `delete_by_name(name)` | `DELETE /api/face/library?name=` | ✅ 同一存储层方法 |
| 删除后校验 | 打印 `deleted N` | `notice` 显示 `N`（取响应 `data.deleted`） | ✅ |
| 库路径 | `backend/face_features.db` | 同一个库（后端持有连接，前端不感知） | ✅ |
| 维度 | `feature_dim` 列 | 维度列 + 异常告警 | ➕ 增强 |
| 空库 | 打印「特征库为空」 | 空态 + 去采集引导 | ✅ 语义一致 |

> **不要在前端直连 SQLite**：浏览器既不能读本地文件，也不该绕过后端的并发控制（阶段 2 的 `check_same_thread=False` + 锁）。`/api/face/library` 是唯一入口。
>
> **表列名**：`face_features(id, feature, timestamp, face_id, feature_dim)`——姓名列叫 `face_id`，**没有** `name` 列。`list_records()` 在 Python 侧把 `face_id` 映射成字典键 `name`，所以前端拿到的 JSON 字段是 `name`，但手工 SQL 必须写 `face_id`。

### 4.8 性能与规模

| 记录数 | `GET /api/face/library` 响应 | 首屏渲染 | 备注 |
|--------|------------------------------|----------|------|
| 10 | ~2 KB | < 30 ms | 典型演示规模 |
| 200 | ~40 KB | ~120 ms | 聚合 + 排序仍在 1 帧内完成 |
| 1000 | ~200 KB | ~400 ms | 建议引入分页 |
| 5000 | ~1 MB | > 1.5 s | 必须分页 + 服务端搜索 |

每条记录仅 4 个字段（`id/name/timestamp/feature_dim`），不含 2048 B 的 BLOB，所以 1000 条约 200 KB（`docs/03-04` 的设计目标就是「列表不读特征本体」）。

`people` 聚合复杂度 O(n)，只在 `items` 变化时重算（`computed` 缓存），搜索过滤 O(n) 亦如此；只有 `keyword` 变化才重算过滤结果。

| 优化项 | 何时做 | 做法 |
|--------|--------|------|
| 分页 | > 1000 条 | 后端加 `offset/limit`（阶段 5） |
| 服务端搜索 | > 1000 条 | `GET /api/face/library?q=张三` |
| 虚拟滚动 | > 2000 条且必须一屏 | 引入 `vue-virtual-scroller`（当前不引入任何 UI 依赖） |
| 索引 | 库很大且按名查询频繁 | `CREATE INDEX idx_face_id ON face_features(face_id)`（`docs/02-03`） |

## 七、异常点与坑点

| # | 坑点 | 现象 | 处理 |
|---|------|------|------|
| 1 | 直接渲染 `items` | 一人多条特征显示成多行，用户以为重复录入 | 用 `people` 聚合视图（4.2） |
| 2 | 聚合时 `dims` 用数组去重 | `512` 与 `"512"` 同时出现在列里 | 统一 `Number` 后 `Set`，或后端保证数值类型 |
| 3 | `timestamp` 字符串直接 `new Date()` | UTC 当本地时间，显示差 8 小时 | 阶段 4 原样展示并标注 UTC；要转换需补 `Z` |
| 4 | 聚合用 `Array.find` 而非 `Map` | 1000 人时 O(n²) | `Map` 一次遍历（4.2） |
| 5 | 搜索 `toLowerCase` 忘记 `trim` | 输入空格后列表全空 | `kw` 用 `trim().toLowerCase()` |
| 6 | 搜索触发重新请求 | 每敲一个字 GET 一次 | 纯前端 `computed` 过滤（4.3 注） |
| 7 | 删除只用 `confirm()` | 样式不可控、无法展示条数、移动端差 | 原生 `<dialog>`（4.4） |
| 8 | `<dialog>` 用 `v-if` 控制 | 每次打开重建节点，`ref` 为 null，`showModal()` 报错 | 常驻 DOM + `showModal()/close()`（示例为常驻） |
| 9 | 对话框内按钮 `type` 写成 `submit` | 表单提交导致页面刷新/路由跳转 | `type="button"`（示例已写） |
| 10 | 删除后只做本地 `splice` | 与后端不一致（并发采集），刷新后「复活」 | `await load()` 以后端为准 |
| 11 | 把 `name` 拼进 path | `DELETE /face/library/{name}` → 405/404 | 后端只有 query 版：`params: { name }`（4.3 的 `deleteLibraryItem`） |
| 12 | 失败时不清空 `items` | 显示过期数据且仍可点删除 → 误删 | 失败清空 + 禁用删除 |
| 13 | `askDelete` 未拦 `errorText` | 加载失败后仍能对旧数据发起删除 | 函数首行判断 |
| 14 | `deleting` 未复位 | 删除失败后按钮永久「删除中…」 | `finally { deleting.value = false }` |
| 15 | `notice` 不复位 | 提示条一直挂着，用户以为刚又删了一次 | 手动「知道了」关闭 + 每次操作前清空 |
| 16 | `1005` 当成失败告警 | 用户看到红条「用户不存在」，误以为系统坏了 | `1005` 视为成功语义（4.4） |
| 17 | `<table>` 里放 `<div>` | HTML 解析器把 `div` 提到表格外，样式错乱 | 单元格内只用行内元素（示例合规） |
| 18 | 大量行无 `key` 或 `key` 用 index | 删除后行数据错位（复用旧 DOM） | `key` 用 `name`（按人）/`id`（明细） |
