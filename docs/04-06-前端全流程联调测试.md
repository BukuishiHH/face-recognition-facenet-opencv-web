## 一、联调目标与范围

阶段 4 前五步各自验证了「单页可用」，本步验证**跨页面、跨进程、跨网络**的整体可用性：

| 维度 | 要回答的问题 |
|------|--------------|
| 主链路 | 采集 → 识别（图片/实时）→ 管理，一路走通不断链 |
| 契约 | 前端发出去的每个字段，后端是否按 `docs/03-05` 的定义理解 |
| 错误传播 | 后端每个错误码，前端是否落在预期分支（不是「一律弹网络错误」） |
| 状态自洽 | 采集后识别页能否立刻认出新的人；删除后识别是否立即失效 |
| 生命周期 | 切路由/切 Tab/刷新/热更新后无残留流、无残留定时器 |
| 兼容性 | Chrome/Edge/Firefox/Safari + 局域网 IP 访问 |
| 性能 | 冷启动、首屏、识别往返是否在预算内 |
| 可交付性 | 换一台机器按 README 能否复现全部通过项 |

**不在本步范围**：后端单元测试（阶段 2/3 已覆盖）、部署与 HTTPS（阶段 5）、多人并发压测（阶段 5 性能专项）。

### 4.4 接口契约核对

逐字段对照 `docs/03-05`。**任何一个字段名拼错，后端都只会返回 422 或 `1001`，不会明确指出是哪个字段**，因此必须按表打勾。

| # | 接口 | 前端发送 | 后端期望 | 核对点 | ✅ |
|---|------|----------|----------|--------|---|
| 1 | `POST /face/register/image` | `FormData`：`file`（Blob）、`name`（string） | multipart 同名 | 字段必须是 `file` 不是 `image`；`name` 不能为空串 | ☐ |
| 2 | 同上 | 文件名无关（后端按内容解码） | — | 传 `blob` 时文件名可为 `capture.jpg` | ☐ |
| 3 | `POST /face/register/camera-frame` | JSON `{ name, image_base64 }` | 同名 | 采集页「拍照」走这个接口，字段含 `name` | ☐ |
| 4 | `POST /recognize/image` | `FormData`：`file`、`threshold`、`save_result`（字符串） | multipart 同名 | **不是 JSON**；`save_result` 传 `'true'`/`'false'` | ☐ |
| 5 | `POST /recognize/frame` | JSON `{ image_base64, threshold }` | 同名 | 帧接口**没有** `name` 字段；`image_base64` 可带 dataURL 前缀 | ☐ |
| 6 | 响应（识别） | 读 `data.faces[]`、`data.library_empty`、`data.result_image_url`（仅 `save_result=true`） | — | `faces[].box` 为 `{x,y,w,h}`；`similarity` 为 0~1 | ☐ |
| 7 | `GET /face/library` | 无参数 | — | 读 `data.items[]`、`data.total`，字段 `id/name/timestamp/feature_dim` | ☐ |
| 8 | `DELETE /face/library` | query `name` | `params: { name }` | 读 `data.deleted`；不是 path 参数 | ☐ |
| 9 | 错误响应 | 读 `code` / `message` | `{code, message, data}` | 非 0 一律 reject 成 `ApiError` | ☐ |
| 10 | 静态资源 | `/static/xxx.jpg` 不带 `/api` | 根路径挂载 | 必须经 `resolveStaticUrl()` 拼 base | ☐ |
| 11 | 422 | FastAPI 校验失败 | 无 `code` 字段 | 前端需兜底 `code ?? 422` | ☐ |

```js
// 契约自检：在浏览器 Console 粘贴，逐个调用并打印原始响应
const base = '/api'
const raw = async (label, fn) => {
  try { console.log(label, 'OK', await fn()) }
  catch (e) { console.log(label, 'ERR', e.status, e.code, e.message) }
}
await raw('health', () => fetch(`${base}/health`).then((r) => r.json()))
await raw('library', () => fetch(`${base}/face/library`).then((r) => r.json()))
```

| 常见契约错位 | 症状 | 修正 |
|--------------|------|------|
| 发 `image` 而非 `image_base64` | 422 `field required` | 改字段名（4-1 的 `api/face.js`） |
| `image_base64` 传 Blob/裸字节 | 422 类型错误 | 只传字符串（`canvas.toDataURL()` / 文件读取结果均可，后端支持 `data:` 前缀） |
| `threshold` 传字符串 | 422 类型错误 | `Number()` |
| 删除姓名拼进 path | 405 / 404 | 用 `params: { name }`（`deleteLibraryItem`） |
| 静态图用 `/api/static/...` | 404 | `resolveStaticUrl()` |
| 把 422 当网络错误 | 提示「无法连接服务」 | 拦截器按 `status` 归类 |

### 4.6 跨页面状态自洽

前端**不维护全局人脸数据**，所有页面每次操作都以后端为准。这一节验证「没有隐性缓存导致的过期视图」。

| 操作序列 | 期望 | 若不一致说明 |
|----------|------|--------------|
| 采集「王五」→ 切实时页 → 正脸对镜头 | ≤ 2 拍内出现「王五」绿框 | 路由被 `keep-alive` 缓存了旧组件状态，或后端缓存了特征列表 |
| 采集「王五」→ 切管理页 | 立即能看到王五（无需点刷新） | 管理页复用了 `onMounted` 之外的数据，或路由缓存 |
| 管理页删「王五」→ 切图片页上传其照片 | 红框「未知」 | 前端缓存了 `people`，或后端未提交事务 |
| 管理页删「王五」→ 切实时页（循环仍在跑） | ≤ 2 拍内王五变红框 | 实时页读的是旧 `faces`，未重新请求 |
| 阈值在图片页调成 0.9 → 切实时页 | 实时页滑块仍为默认 0.6（各页独立） | 若共享，需确认是否符合产品预期（当前：独立） |
| 页面 A 出错后切到页面 B 再切回 | A 状态已重置（无残留错误条） | 组件被缓存，`onBeforeUnmount` 未清状态 |
| 管理页删除时，实时页正在识别该人 | 下一次请求即不再命中（最多滞后 1 拍） | 后端识别时未查库（阶段 3 已保证实时查库） |

```js
// 自检：在路由切换处打印组件卸载，确认没有 keep-alive
router.afterEach((to) => console.info('[route]', to.fullPath))
// 组件内 onBeforeUnmount 打印一次，切页时应出现
```

> **不要给路由加 `<keep-alive>`**（`docs/04-01` 已明确）：`useCamera` 持有 `MediaStream`、实时页持有 `setTimeout` 链，被缓存后组件不卸载 → 摄像头不释放、循环继续跑。这是「切页后摄像头灯还亮」的最大来源。

# 帧识别（连续 3 次串行，观察是否出现 429/1008；帧接口只收 image_base64/threshold）
