## 一、功能背景

阶段 2 的单元测试（`test_face_detection.py` / `test_face_recognition.py` / `test_db_utils.py` / `test_main.py`）验证的是**算法与数据层函数**；阶段 3 新写的 `api_server.py` 引入了一整层**协议契约**，它是单测覆盖不到的：

| 新增风险点 | 单测能否发现 | 示例 |
|------------|--------------|------|
| 路由路径 / 方法写错 | ❌ | `@app.post` 写成 `@app.get`，前端 405 |
| multipart / JSON 解析 | ❌ | `file.file.read()` 用成 `await file.read()`，500 |
| 响应信封字段漂移 | ❌ | `data` 里少 `matched`，前端框全绿 |
| 错误码映射错位 | ❌ | 无人脸返回 `1001` 而非 `1002` |
| 坐标缩放还原 | ❌ | 大图检测框偏移 |
| 数据库单例跨线程 | ❌ | `SQLite objects created in a thread...` |
| 生命周期加载模型 | ❌ | 忘记用 `with TestClient` → `app.state.detector` 不存在 |
| 特征库为空的行为 | ❌ | 空库返回 500 而非 `library_empty=true` |

`development_steps.md` 对本步的要求是：**使用 `/docs` 逐项测试全部接口；异常场景（无人脸、损坏图片、空特征库、越界图像）；确认数据库-检测-特征链路完整**。

本文档把这条要求拆成两半：

1. **自动化**：`tests/test_api_server.py` 用 `TestClient` 在进程内跑完整 HTTP 链路（不启 uvicorn、不占端口、可断点调试）；
2. **手工**：`/docs` 逐项点测 + 真实 uvicorn 启动，覆盖 Swagger UI、CORS、静态图片访问这些自动化测试不易覆盖的部分。

**核心原则：测试绝不能污染真实 `backend/face_features.db` 与 `result_output/`。**

## 二、开发目标

| 目标 | 说明 |
|------|------|
| 全接口覆盖 | 7 个接口（health / register×2 / recognize×2 / library×2）均有正常用例 |
| 异常矩阵覆盖 | 无人脸、损坏图、空文件、空姓名、超长姓名、同名、非法 base64、阈值越界、空库、缺字段、记录不存在、推理繁忙 |
| 链路闭环 | 「录入 → 列表 → 识别命中 → 删除 → 再识别不命中」单用例串通 |
| 数据隔离 | 每个用例独立临时 SQLite；标注图写临时目录；用例可任意顺序执行 |
| 模型只加载一次 | 会话级 `TestClient` + `with` 触发 lifespan，避免 37 个用例各加载一次 FaceNet |
| 可重复 | 姓名统一 `测试_{uuid8}`，重复执行不触发 `1004` |
| 快速反馈 | CPU 环境整份接口测试 < 3 min；失败信息含 `code/message` 原文 |
| 手工清单 | `/docs` 联调核对表 13 项，作为阶段 3 收尾证据 |

### 4.2 夹具设计

**为什么不能直接 `TestClient(app)`：**

| 问题 | 后果 | 对策 |
|------|------|------|
| 不用 `with` | lifespan 不执行 → `app.state.detector` 缺失 → 全部 500 | `with TestClient(...) as client` |
| 用真实 `face_db` | 测试写入/删除真实库，破坏演示数据 | 复用 `isolated_db`，把 `db_utils.face_db` 换成临时库 |
| 每个用例建 client | 每个用例加载一次 FaceNet（5~20 s） | 会话级 `api_client` |
| 标注图写 `result_output/` | 仓库里堆满测试图片 | 启动前把 `api_server.RESULT_DIR` 指向临时目录 |

```python
# tests/conftest.py（阶段 3-5 追加）
import uuid


@pytest.fixture(scope='session')
def api_client(tmp_path_factory):
    """
    会话级 TestClient:
      - 整个会话只触发一次 lifespan(模型加载 5~20s)
      - RESULT_DIR 指向临时目录, 避免标注图写入 backend/result_output/
    说明: 会话夹具不能用 monkeypatch(函数级), 这里手动保存/恢复模块属性。
    """
    from fastapi.testclient import TestClient

    import api_server

    original_result_dir = api_server.RESULT_DIR
    api_server.RESULT_DIR = str(tmp_path_factory.mktemp('api_result'))
    try:
        with TestClient(api_server.app) as client:
            yield client
    finally:
        api_server.RESULT_DIR = original_result_dir


@pytest.fixture()
def seeded_name(api_client, isolated_db, one_face_path):
    """录入一个唯一姓名并返回它; 数据库由 isolated_db 在用例结束后丢弃"""
    name = f'测试_{uuid.uuid4().hex[:8]}'
    with open(one_face_path, 'rb') as f:
        payload = api_client.post(
            '/api/face/register/image',
            files={'file': ('one_face.jpg', f.read(), 'image/jpeg')},
            data={'name': name},
        ).json()
    assert payload['code'] == 0, payload
    return name
```

夹具依赖关系：

```text
api_client(session)          isolated_db(function)        one_face_path(session)
      │                            │                            │
      └────────────┬───────────────┴────────────────────────────┘
                   ▼
             seeded_name(function)  → 已有一条「测试_xxxxxxxx」记录
```

> `isolated_db` 已在阶段 2 实现：创建 `tmp_path/isolated.db`，并把 `db_utils.face_db`、`face_recognition.face_db`、`main.face_db` 三处引用一起替换。
> 由于 `api_server` 统一通过 **`db_utils.face_db` 属性**取库（`docs/03-01` 4.1 导入约定），无需额外 patch `api_server.face_db`，这是当初刻意设计的可测试性收益。

**辅助函数**（放在 `tests/test_api_server.py` 顶部，不放进 `conftest.py`，避免 `conftest` 反向依赖接口模块）：

```python
def _unique_name():
    """唯一姓名: 保证用例可重复执行, 不会因残留数据触发 1004"""
    return f'测试_{uuid.uuid4().hex[:8]}'


def _data_url(path):
    """图片 → dataURL(带前缀), 与前端 canvas.toDataURL() 输出一致"""
    with open(path, 'rb') as f:
        return 'data:image/jpeg;base64,' + base64.b64encode(f.read()).decode()


def _upload(client, path, name=None, **form):
    """以 multipart 方式上传样例图, 返回 JSON"""
    with open(path, 'rb') as f:
        files = {'file': (os.path.basename(path), f.read(), 'image/jpeg')}
    data = {} if name is None else {'name': name}
    data.update({k: str(v) for k, v in form.items()})
    return client.post('/api/face/register/image', files=files, data=data).json()
```

```python
                files={'file': ('one_face.jpg', f.read(), 'image/jpeg')},
                data={'save_result': 'true'}).json()
        url = payload['data']['result_image_url']
        assert url.startswith('/static/') and url.endswith('.jpg')
        assert os.path.exists(os.path.join(api_server.RESULT_DIR, os.path.basename(url)))

    def test_large_image_box_scaled(self, api_client, seeded_name, one_face_path, imread):
        """长边 > 1280 时检测在缩略图上进行, box 必须还原到原图坐标系"""
        small = imread(one_face_path)
        big = cv2.resize(small, None, fx=3, fy=3, interpolation=cv2.INTER_CUBIC)

        def _post(image):
            ok_flag, buf = cv2.imencode('.jpg', image)
            assert ok_flag
            return api_client.post('/api/recognize/image',
                                   files={'file': ('img.jpg', buf.tobytes(), 'image/jpeg')}).json()

        small_payload = _post(small)
        big_payload = _post(big)
        assert small_payload['data']['faces'] and big_payload['data']['faces']
        # Haar 在放大 + JPEG 压缩后可能产生小面积误检, 按面积取真实人脸框
        small_box = max(small_payload['data']['faces'],
                        key=lambda face: face['box']['w'] * face['box']['h'])['box']
        big_box = max(big_payload['data']['faces'],
                      key=lambda face: face['box']['w'] * face['box']['h'])['box']

        assert all(face['box']['x'] + face['box']['w'] <= big.shape[1]
                   and face['box']['y'] + face['box']['h'] <= big.shape[0]
                   for face in big_payload['data']['faces'])       # 所有框不越界
        assert big_box['w'] / big.shape[1] == pytest.approx(        # 相对尺寸一致
            small_box['w'] / small.shape[1], abs=0.05)
```
