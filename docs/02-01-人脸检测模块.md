## 一、功能背景

人脸识别系统必须先回答「人脸在哪」，才能进行「这是谁」。检测模块是整个链路的第一个环节，其输出（人脸框坐标）直接决定后续 ROI 裁剪质量与特征提取质量。

选型对比：

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **OpenCV Haar 级联** | OpenCV 自带 XML，**零额外下载**；CPU 上毫秒级；无 GPU 依赖 | 侧脸/遮挡/极端光照下召回下降 | ✅ 选用 |
| DNN (Caffe/TF) 检测 | 精度更高 | 需额外下载权重，增加部署复杂度 | 后置优化项 |
| MTCNN | 精度高、可输出关键点 | 依赖 torch，与"环境轻量化"目标冲突 | 由 FaceNet 侧可选复用 |

**最终选择**：`cv2.CascadeClassifier` + `haarcascade_frontalface_alt2.xml`，原因是它与阶段 1 已锁定的 `opencv-python 4.x` 完全解耦，无需任何模型文件即可工作。

---

## 二、开发目标

| 目标 | 说明 |
|------|------|
| 人脸定位 | 输入 BGR 图像，输出一个或多个人脸外接矩形 `(x, y, w, h)` |
| 光照鲁棒 | 通过直方图均衡化削弱明暗差异影响 |
| 噪声抑制 | 通过高斯模糊降低画面噪点误检 |
| 边界安全 | 过滤过小框与越界框，保证后续切片不抛异常 |
| ROI 输出 | 提供按框裁剪人脸子图的能力，供特征模块直接消费 |
| 无脸不崩溃 | 未检出人脸时返回空列表，而不是抛异常 |

---

## 三、功能职责

`backend/face_detection.py` 对外仅暴露一个类 `FaceDetection`，承担三件事：

1. **模型加载**：启动时加载 Haar 级联 XML，并校验加载是否成功；
2. **图像预处理**：灰度化 → 直方图均衡 → 高斯模糊；
3. **检测与裁剪**：多尺度检测 → 边界校验过滤 → 输出坐标列表 / ROI 子图。

**不做的事**（职责边界）：

- 不做人脸识别与身份判断（→ `face_recognition.py`）；
- 不做特征存储（→ `db_utils.py`）；
- 不做绘制、保存、菜单交互（→ `main.py` / `api_server.py`）。

## 四、功能逻辑

### 4.1 类结构

```python
class FaceDetection:
    def __init__(self, model_name='haarcascade_frontalface_alt2.xml')  # 加载级联模型
    @staticmethod
    def preprocess(image)                                               # 预处理 → 灰度图
    def detect_faces(self, image, scale_factor=1.1,
                     min_neighbors=5, min_size=(50, 50))                # 检测 → 坐标列表
    @staticmethod
    def crop_face_rois(image, faces)                                    # 裁剪 → ROI 列表
```

### 4.2 处理流程

```text
BGR 原图
   │
   ├─ cvtColor(BGR2GRAY)          色彩空间转换：Haar 只需灰度信息，降 3 倍计算量
   ├─ equalizeHist(gray)          直方图均衡：拉开明暗对比，削弱光照不均
   └─ GaussianBlur(gray,(3,3),0)  高斯模糊：抹平高频噪点，抑制误检
   │
   ▼
CascadeClassifier.detectMultiScale(scaleFactor=1.1, minNeighbors=5, minSize=(50,50))
   │
   ▼
边界校验循环
   ├─ w < 10 或 h < 10                → 丢弃（过小框，无识别价值）
   └─ x<0 / y<0 / x+w>W / y+h>H       → 丢弃（越界，切片会得到空数组）
   │
   ▼
valid_faces = [(x, y, w, h), ...]
   │
   └─ crop_face_rois() → [(roi, (x,y,w,h)), ...]   供特征模块使用
```

### 4.3 `detectMultiScale` 参数说明

| 参数 | 代码取值 | 含义 | 调参影响 |
|------|----------|------|----------|
| `scaleFactor` | 1.1 | 每次图像缩小比例 | 越小越慢但召回越高；>1.3 会漏检小脸 |
| `minNeighbors` | 5 | 邻域矩形数阈值 | 越大误检越少但漏检越多；实测 3~6 较均衡 |
| `minSize` | (50, 50) | 最小人脸像素 | 防止把五官/纹理误判为人脸 |
| `maxSize` | 未设置 | — | 默认不限；如需过滤"疑似背景大框"可补充 |

### 4.4 输入与输出

| 方法 | 输入 | 输出 | 异常 |
|------|------|------|------|
| `FaceDetection(model_name)` | Haar XML 文件名（str） | 实例 | `RuntimeError`：opencv 5.x 无 `CascadeClassifier`；`ValueError`：模型加载失败 |
| `preprocess(image)` | BGR `np.ndarray` | 单通道灰度 `np.ndarray` | 非 3 通道图会在 `cvtColor` 抛 `cv2.error` |
| `detect_faces(image, ...)` | BGR `np.ndarray` | `[(x, y, w, h), ...]`（无人脸为 `[]`） | `TypeError`：入参非 `np.ndarray` |
| `crop_face_rois(image, faces)` | BGR 图 + 坐标列表 | `[(roi, (x,y,w,h)), ...]` | 坐标越界时切片为空数组（已由检测阶段过滤） |

> `detectMultiScale` 返回的是 `numpy.ndarray`（`shape=(N,4)`）；本模块统一转换为 Python `list[tuple]`，便于 `db_utils`/`main` 序列化与打印。

## 七、异常点与坑点

| # | 问题 | 现象 | 定位与处置 |
|---|------|------|------------|
| 1 | **构造函数拼写错误（已修复）** | 原代码写作 `def __inti__(self, ...)`，Python 不识别为构造器，`self.face_engine` 从未赋值，调用 `detect_faces` 立即抛 `AttributeError` | 修正为 `def __init__(...)`；这是本模块最隐蔽的坑——**拼写错误不会报错，只会让初始化被静默跳过** |
| 2 | **opencv 5.x 无 Haar 级联** | `cv2.CascadeClassifier` 属性不存在 → `AttributeError` | 类内显式 `hasattr(cv2, 'CascadeClassifier')` 前置校验，抛出带说明的 `RuntimeError`，提示降级到 4.x |
| 3 | `cvtColor` 对单通道图报错 | 传入灰度图会抛 `cv2.error: Invalid number of channels` | 约定本模块只接收 **BGR 三通道**图；调用方若已有灰度图需先转回 BGR 或改用其他入口 |
| 4 | 中文路径读图失败 | `cv2.imread('D:/人脸/a.jpg')` 返回 `None` | Windows 下 `cv2.imread` 不支持非 ASCII 路径；由 `main.py` 统一用 `np.fromfile + cv2.imdecode` 读取（阶段 2-4 处理） |
| 5 | `minSize` 过大会漏检远处小脸 | 近距离多人合照中后排人脸丢失 | 按场景下调 `min_size`（如 `(30,30)`），同时提高 `minNeighbors` 抑制误检 |
| 6 | 检测耗时随分辨率线性上升 | 4K 图检测可达数百毫秒 | 大图先 `resize` 到长边 ≤1280 再检测，坐标按比例还原 |
| 7 | 返回 `ndarray` 而非 `list` 的兼容性 | `ndarray` 无法直接 `json.dumps` | 统一转 `[(int(x), int(y), int(w), int(h)), ...]`，保证 JSON 可序列化（阶段 3 接口需要） |
