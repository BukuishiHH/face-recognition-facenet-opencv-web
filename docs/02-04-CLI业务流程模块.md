## 一、功能背景

阶段 2 的前三个模块各自只交付"一种能力"：`face_detection.py` 回答「人脸在哪」、`face_recognition.py` 回答「这是谁」、`db_utils.py` 负责「把身份存下来」。但三者彼此独立、互不感知——**没有任何一个模块知道完整的业务流程长什么样**。

如果让 Web 接口层（阶段 3）或前端（阶段 4）直接拼接这三个模块，会出现两个问题：

1. **业务逻辑被复制多份**：图片录入、摄像头录入、图片识别、实时识别四条链路的编排细节（读图 → 检测 → 裁剪 → 提特征 → 比对 → 画框 → 保存 → 释放）一旦散落在多处，后续任何一处调整都要同步多处；
2. **算法链路缺少独立验证入口**：在接入 Web 层之前，需要一个**不依赖任何前端、不依赖 HTTP** 的最小可运行入口，用来快速验证「算法链路本身是否跑通」。

因此 `backend/main.py` 的定位是 **业务编排层（Orchestration Layer）**：把三个算法/存储模块组装成完整业务闭环，并以 CLI 菜单形式对外提供交互入口。它同时承担两个角色：

| 角色 | 说明 |
|------|------|
| **算法链路的验证入口** | CLI 全功能跑通 = 阶段 2 算法链路验收通过，是进入阶段 3 的前置条件 |
| **阶段 3 的复用蓝本** | Web 接口层复用其「编排逻辑」，仅剥离 `input()` 控制台输入与 `cv2.imshow()` GUI 显示 |

## 二、开发目标

| 目标 | 说明 |
|------|------|
| 业务闭环 | 覆盖「采集入库 → 特征库管理 → 图片识别 → 实时识别 → 删除」全流程 |
| 菜单调度 | 7 项菜单（含退出），非法选项不崩溃、给出提示并回到菜单 |
| 中文路径读图 | Windows 下 `cv2.imread` 不支持非 ASCII 路径，必须用 `np.fromfile + cv2.imdecode` |
| 中文结果标注 | 结果图上绘制中文身份标签，规避 OpenCV `putText` 不支持中文的问题 |
| 结果可视化与留存 | 画框 + 标注身份/相似度，并把结果图落盘到 `result_output/` |
| 资源安全释放 | 摄像头、窗口、数据库连接在使用后必须释放 |
| 输入健壮 | 文件不存在、格式损坏、无人脸、姓名为空等场景均给出可读提示而非异常栈 |

## 三、功能职责

`backend/main.py` 对外提供 **1 组通用工具 + 6 项业务功能 + 1 个主菜单**：

| 分类 | 函数 | 职责 |
|------|------|------|
| 通用工具 | `read_image(image_path)` | 读取本地图片并校验合法性（兼容中文路径） |
| 通用工具 | `put_chinese_text(img, text, position, ...)` | 在 OpenCV 图像上绘制中文文本（PIL 中转） |
| 通用工具 | `draw_results(image, faces, results)` | 绘制人脸框 + 身份标签 + 相似度 |
| 通用工具 | `save_result(image, prefix)` | 保存标注后的结果图 |
| 业务功能 | `register_face_from_image()` | 图片录入人脸：读图 → 检测 → 截 ROI → 提特征 → 入库 |
| 业务功能 | `register_face_from_camera()` | 摄像头录入人脸：`s` 键采集入库，`q` 退出 |
| 业务功能 | `recognize_from_image()` | 图片识别：检测 → 逐张比对 → 画框标注 → 保存结果图 |
| 业务功能 | `recognize_from_camera()` | 摄像头实时识别：循环检测比对并叠加标注 |
| 业务功能 | `show_all_features()` | 查看特征库：记录数、矩阵形状、每条记录 ID 与姓名 |
| 业务功能 | `delete_face()` | 按姓名删除已录入特征 |
| 主入口 | `__main__` 菜单循环 | 打印菜单 → 读取选项 → 分发到对应功能 → 退出时释放资源 |

**不做的事**（职责边界）：

- 不做人脸检测算法本身（→ `face_detection.py`）；
- 不做特征提取与相似度计算（→ `face_recognition.py`）；
- 不做特征持久化（→ `db_utils.py`）；
- 不做 HTTP 接口与数据模型（→ 阶段 3 `api_server.py`）。

## 四、功能逻辑

### 4.1 模块结构与全局对象

```python
BASE_DIR   = os.path.dirname(os.path.abspath(__file__))      # backend/
RESULT_DIR = os.path.join(BASE_DIR, 'result_output')         # 结果图目录
face_detector = FaceDetection('haarcascade_frontalface_alt2.xml')   # 全局检测器(模块导入即加载)

from db_utils import face_db                                 # 全局特征库单例
from face_recognition import FaceRecognition                 # 识别类(模型懒加载, 首次调用才加载)
```

> **设计说明**：`face_detector` 在模块导入时即创建，全流程复用同一个 Haar 级联实例；`FaceRecognition` 的 FaceNet 模型通过类变量 `_model` 懒加载并全局复用，避免每次识别重复加载权重。

### 4.2 六步业务流程（与模块头部注释一一对应）

```text
1. 图像源获取   read_image(本地图片)  /  cv2.VideoCapture(0)(摄像头循环)
        │
2. 图像预处理   FaceDetection.preprocess: BGR→灰度 → 直方图均衡 → 高斯降噪
        │
3. 人脸检测     FaceDetection.detect_faces        → [(x, y, w, h), ...]
   ROI 截取     FaceDetection.crop_face_rois      → [(roi, (x,y,w,h)), ...]
        │
4. 人脸识别     FaceRecognition.extract_feature(512 维) → 与 face_db 特征库比对
        │
5. 结果可视化   draw_results(画框+身份+相似度) → save_result(落盘 result_output/)
        │
6. 资源释放     cap.release() + cv2.destroyAllWindows() + face_db.close()(退出时)
```

### 4.3 图片识别流程（`recognize_from_image`）

```text
input: 图片路径
   │
read_image ──► None? ──► 打印 "图片文件不存在" / "无法读取图片" 并返回
   │
detect_faces ──► 空列表? ──► 打印 "未检测到人脸" 并返回
   │
for each roi:  FaceRecognition.recognize_face(roi)   # 与库内全部特征算余弦相似度取最高分
   │                                                 # 相似度 < 0.6 → None(Unknown)
   ▼
draw_results(image.copy(), faces, results)   # 命中→绿框绿字; 未命中→红框红字
   │
cv2.imshow → cv2.waitKey(0) → destroyAllWindows
   │
save_result(drawn, prefix='recognize')       # 保存到 result_output/recognize_<tick>.jpg
   │
打印统计: "识别完成: N/M 人匹配成功, 结果: [...]"
```

> 逐张 ROI 独立调用 `recognize_face`，因此**同一张图里的多个人脸可以各自匹配到不同身份**，互不干扰。

### 4.4 摄像头实时识别流程（`recognize_from_camera`）

```text
cv2.VideoCapture(0) ──► not opened? ──► 打印 "摄像头打开失败" 并返回
   │
while True:
    ret, frame = cap.read() ──► not ret? ──► 打印错误并 break
    faces   = detect_faces(frame)
    results = [recognize_face(roi) for roi, _ in crop_face_rois(frame, faces)]
    drawn   = draw_results(frame, faces, results)
    cv2.putText("Press 'q' to quit")  →  cv2.imshow(...)
    if cv2.waitKey(1) & 0xFF == ord('q'): break
   │
cap.release() + cv2.destroyAllWindows()          # 循环退出后必定释放
```

### 4.5 主菜单分发逻辑

```text
while True:
    打印菜单(1~6 / 0)
    choice = input("请输入选项: ").strip()
    1 → register_face_from_image()      图片录入
    2 → register_face_from_camera()     摄像头录入
    3 → show_all_features()             查看特征库
    4 → recognize_from_image()          图片识别
    5 → recognize_from_camera()         实时识别
    6 → delete_face()                   删除记录
    0 → face_db.close() + break          退出并释放数据库连接
    其他 → 打印 "选项不存在, 请重新输入"   (不崩溃, 回到菜单)
```

### 4.6 通用工具设计要点

| 工具 | 关键实现 | 原因 |
|------|----------|------|
| `read_image` | `cv2.imdecode(np.fromfile(path, np.uint8), IMREAD_COLOR)` | Windows 下 `cv2.imread` 对**中文路径静默返回 None**（本项目路径含中文） |
| `put_chinese_text` | `cv2 → PIL(ImageDraw) → 绘制 → cv2`，字体 `C:/Windows/Fonts/simhei.ttf` | OpenCV `putText` **不支持中文**；PIL 支持 TTF 渲染 |
| `put_chinese_text` 颜色 | `rgb_color = (color[2], color[1], color[0])` | 调用方按 **BGR** 传色（与 OpenCV 一致），PIL 按 **RGB** 解释，必须转换否则红/蓝互换 |
| `draw_results` | `zip(faces, results)` 一一对应，`result is None` 判 Unknown | 识别结果与检测框顺序严格一致，`None` 表示无匹配 |
| `save_result` | `cv2.imencode('.jpg')` + 二进制写文件 | 同样规避中文路径问题；文件名用 `prefix_<tick>.jpg` 防覆盖 |

### 4.7 输入与输出

| 函数 | 输入 | 输出 / 副作用 |
|------|------|---------------|
| `read_image(path)` | 图片路径 | BGR `ndarray` 或 `None`；控制台错误提示 |
| `put_chinese_text(img, ...)` | BGR 图 + 文本 + 位置 + 字号 + **BGR 颜色** | 新 BGR 图（原图不变） |
| `draw_results(img, faces, results)` | BGR 图 + 框列表 + 结果列表 | 标注后的图（命中绿框、未命中红框） |
| `save_result(img, prefix)` | 图 + 文件名前缀 | 写入 `result_output/<prefix>_<tick>.jpg` |
| `register_face_from_image()` | `input`: 图片路径、姓名 | 特征入库；库中已有同名则被 `db_utils` 跳过 |
| `recognize_from_image()` | `input`: 图片路径 | 弹窗预览 + 结果图落盘 + 控制台统计 |
| `show_all_features()` | — | 控制台打印记录数、矩阵形状、每条 ID/姓名 |
| `delete_face()` | `input`: 姓名 | 按姓名删除全部记录 |

## 八、异常点与坑点

| # | 问题 | 现象 | 定位与处置 |
|---|------|------|------------|
| 1 | **Windows 中文路径读图失败** | `cv2.imread('D:/人脸检测识别系统/.../a.jpg')` **静默返回 `None`**（不报错），后续 `cvtColor` 抛 `!_src.empty()` | 本模块统一 `read_image` = `cv2.imdecode(np.fromfile(path, np.uint8), IMREAD_COLOR)`；**本项目路径本身就是中文**，故该坑必然触发（编写测试时实测复现 6 项失败，修正测试读图方式后通过） |
| 2 | **中文绘制颜色 BGR/RGB 混淆（已修复）** | 调用方按 BGR 传 `(0,0,255)`（红），PIL 按 RGB 解释 → 实际渲染为**蓝色**；绿色因 R/B 对称而不受影响，故极隐蔽 | `put_chinese_text` 内新增 `rgb_color = (color[2], color[1], color[0])`；已由 `test_bgr_color_mapping` 用例锁定行为 |
| 3 | **`cv2.putText` 不支持中文** | 直接绘制中文显示为 `????` | 改用 PIL `ImageDraw.text` + `simhei.ttf` 渲染，再转回 OpenCV 图像 |
| 4 | **`simhei.ttf` 缺失 / 路径不存在** | 非 Windows 或精简系统无黑体，抛异常导致整条渲染链路中断 | `try/except` 回退为 `ImageFont.load_default()` 并打印 Warning（中文降级为默认字形，**不中断主流程**） |
| 5 | **`cv2.imshow` 依赖 GUI 环境** | 无显示设备（CI/服务器）调用会报错或阻塞 | 交互窗口属人工验证路径；自动化测试中以 `monkeypatch` 替换 `imshow/waitKey/destroyAllWindows` |
| 6 | **摄像头功能无法自动化测试** | `cv2.VideoCapture(0)` 依赖物理设备，无设备时永久阻塞 | `register/recognize_from_camera` 不纳入自动化测试，由人工按本文档「附」验证 |
| 7 | **结果图文件名冲突** | 文件名用 `cv2.getTickCount() % 1e9`，理论上高频连续保存可能重名 | 单机 CLI 场景概率极低（保存为人工触发）；如需强保证可改用时间戳 + 微秒 |
| 8 | **摄像头录入时 `input()` 阻塞预览** | 按 `s` 后控制台等待输入姓名，窗口画面冻结 | 现阶段可接受（CLI 定位）；阶段 3 由前端表单替代输入 |
| 9 | **同名重复录入被静默跳过** | 同一姓名二次录入返回 `None`，控制台出现 `Warning!` | 由 `db_utils.save_feature` 的查重逻辑保证（详见 `docs/02-03` 坑点 5/6），本模块不额外处理 |
| 10 | **模块导入即产生副作用** | `import main` 会立即加载 Haar 模型、连接 `face_features.db` | 属有意设计（CLI 单例复用）；测试中通过 `isolated_db` 夹具替换 `face_db`，避免污染真实库 |
| 11 | **识别阈值 0.6 为经验值** | 不同数据域（监控画质、光照）最佳阈值不同，固定 0.6 可能漏判/误判 | 建议用 `sample_faces/` 真实样本在 `0.5 ~ 0.7` 区间标定后固化（见 `docs/02-02` 坑点 10） |
| 12 | **区段注释重复（已修复）** | 主入口处注释与「通用工具」区段同名，易误导阅读 | 改为 `主入口` |
